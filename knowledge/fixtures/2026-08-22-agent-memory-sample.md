# 示例：面向 LLM Agent 的长期记忆研究卡片

> 这是用于验证 AnythingLLM 导入、Markdown 渲染和 RAG 问答的**虚构验收样本**，不是对某篇真实论文的解读，不应作为研究结论引用。

## 为什么推荐给你

如果你关注 LLM Agent 的长期记忆，这个样本用于检验知识库能否区分：短期上下文、外部检索记忆，以及会随任务更新的长期记忆。

## 一分钟结论

长期记忆不应被理解为无限追加聊天记录。更可行的方向是把经验编码为可检索、可更新、并附带来源与时间信息的条目，再在每次任务中按需取回。

## 它试图解决什么问题？

Agent 的上下文窗口有限。仅依赖当前对话会遗忘过去任务，而把全部历史对话拼进 Prompt 又会增加成本并引入无关信息。

## 方法直觉

将任务结果转换为结构化记忆条目：任务背景、采取的动作、结果、失败原因、适用条件和时间戳。新任务到来时，系统先用当前目标检索相关条目，再把少量高相关记忆放进上下文。

## 关键结果

这个验收样本不提供真实实验数据。产品真正需要验证的是：用户能否在问答时区分“当前上下文”“检索式记忆”和“长期经验”，并通过来源链接追溯内容。

## 局限与适用边界

- 记忆条目可能过时，因此需要记录时间和版本。
- 错误经验一旦被保存，可能在后续任务中反复被检索到。
- 不适合把原始隐私信息直接写入长期知识库。

## 与检索式记忆的关系

检索式记忆解决“从外部知识中找相关资料”；长期经验记忆解决“Agent 在过去任务中学到了什么”。两者可以共同存在，但不能混为同一个没有来源和时间字段的文本池。

## 建议下一步

阅读真实论文时，应重点记录：记忆写入条件、更新策略、检索策略、遗忘/冲突处理，以及实验任务是否足以证明长期收益。
