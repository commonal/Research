# Task-Conditioned Least-Privilege Learning for Executable Terminal and MCP Agents

> 证据等级：full_text_text。不保存论文原文；请通过来源链接核查。

## 一句话先说清楚

本文针对可执行终端与MCP工具智能体在任务完成正确但动作越权的问题，提出任务相关的least-privilege学习框架：由不可见broker在动作执行前后解析并审计权限，用六维风险向量刻画状态变更、动态执行、越界、敏感数据访问等权威维度，并按任务给定sufficient-authority envelope，只惩罚超出该边界的多余权限。基于Qwen3.5-4B与LoRA+Dr.GRPO在1500个可执行任务上训练，内部验证safe success明显提升，外部基准MetaTool与FORTIS显示通用选工具能力未下降。

## 背景：作者发现了什么问题

一个工具智能体可以在回答中给出正确结果，却在过程中读取无关记录、编辑任务范围以外的文件、调用更高权限的MCP工具，甚至形成权限提升。这类行为被定义为task-relative excess-authority errors：动作行使了超出任务合理最小需要的权威；即使最终答案或状态正确，整条轨迹仍是over-privileged。常见评测只检查最终答案，无法捕获这类副作用，因为错误发生在过程而非结论。现有防护主要在模型提出或执行动作之后起作用：权限门按已学习的风险类别拦截调用，但功能等价的状态更改或命令可经由未设防的路径绕过门；静态门控也可能同时漏掉执行链真正需要的访问并授予无关敏感访问，覆盖依赖已见过的风险类别。因此需要一个与任务相关的权威边界：模型可见完整工具清单，但由环境broker解析每个动作、计算其意图权威并记录实际影响，据此为每个任务指定sufficient-authority envelope，只惩罚超出该边界的行为。现有方法缺少这种前置、过程级、任务相关的least-privilege约束，本文即填补这一gap。

## 论文真正要解决的问题

核心研究问题可以表述为：能否通过任务相关的权威边界和过程级审计，让智能体同时满足两个相互约束的要求——既完成目标任务、提供可验证证据，又避免任何超出sufficient-authority envelope的excess-authority动作？该问题要求在奖励设计中把成功率和动作权威合并，而不能只优化其中一个。本文用可执行broker环境与最小权限RL训练来回答这一问题，并检验所学行为是否依赖提示词。

## 核心想法：把问题变成可计算目标

核心直觉是：least privilege不是一个静态白名单，而是在每个时刻相对当前任务而定的边界。智能体看到完整工具库，环境里的broker则替代用户执行每个动作：动作前解析、计算意图权威并评估执行风险，动作后核对实际效果；六维风险向量覆盖状态变更、动态执行、越过环境边界、非特权敏感数据访问、影响范围广、以及超出本次操作的持久状态。风险向量取动作前与动作后的逐维最大值，整条轨迹的风险向量记录每个权威维度上曾达到的最大值。每个任务预先给定sufficient-authority envelope，只在动作越过该包络时惩罚，因此不要求模型对所有工具一律保守。与静态权限门不同，这里不是靠已经学到的风险类别去拦截调用，而是让模型在提出动作时就学习选择恰好够用、又能提供完成任务所需证据的命令；与只测over-privilege的指标也不同，safe success要求任务完成、证据、从精确状态可验证且无excess-authority事件，防止模型靠拒绝行动来刷安全分。broker内置在训练循环内，奖励在动作执行后由验证器计算，使RL能同时优化能力与权威合适度。

## 方法如何落地

方法由四个可插拔组件构成。1) 模型与训练目标：以Qwen3.5-4B为策略，配LoRA适配器，采用direct Dr.GRPO进行强化学习，训练要求模型在完成目标的同时考量动作权限的充分性与适当性；奖励函数的具体权重由人工选择而非学习得到。2) 执行broker：环境侧对策略提出的每个动作先做解析和pre-audit，计算动作的intended authority、评估execution risk并选择执行模式，动作发往terminal或MCP服务后再接收结果并记录实际造成的影响；它同时承担post-execution auditing。3) 六维风险向量与任务包络：风险轴包括状态变更、动态执行、达到或超过环境边界、未授权敏感数据访问、广泛且大范围影响、超出本操作的持续状态；pre与post风险逐维取最大值，整条轨迹记录每个维度达到的最大值。每个任务配reference oracle与sufficient-authority envelope，只有越过包络的权限被惩罚。4) 自动验证器：检查exact answers、hidden tests、required output files、targeted test results、exact MCP state、evidence paths、required writes以及拒绝额外写入，proposal-only任务禁止环境变更，escalation任务要求有据可查的人工介入原因，evidence terminal-gated使最终答案后的读取不能为前面的答案辩护。框架声称可以脱离Dr.GRPO，作为任意奖励函数中的excess-privilege计算与多步验证组件使用。

## 工作流程（一步一步）

1) 任务输入：从1,500个训练任务目录中取出任务，任务附有reference oracle和sufficient-authority envelope，细分为定向读取、代码修改、测试选择、恢复、分级升级、提示注入约束、秘密诱饵、外部读取、精确MCP状态变更和多工具工作流等行为族。
2) 策略决策：Qwen3.5-4B在完整系统提示、工具清单、least-privilege规则与broker环境下选择动作；冷启动依赖长提示而非SFT。
3) 动作前审计与判定：broker解析动作，确定性计算intended authority、评估execution risk、选择执行模式，并检查动作是否越过当前任务的权限包络；若任务为proposal-only则禁止环境变更。
4) 环境执行：动作被发往terminal或MCP服务执行，broker接收返回结果并记录实际效果，包括状态写入、动态执行、边界跨越、敏感数据访问、影响范围与持久状态。
5) 动作后审计：将post-action风险向量与pre-action向量逐维取最大值，沿轨迹累计成final trajectory risk vector；若某步出现成功但越权的excess-authority事件，则该事件被记录。
6) 自动验证：verifier按需检查精确答案、隐藏测试、必需输出文件、定向测试结果、MCP状态、证据路径、必需写入以及是否拒绝了额外写入；escalation任务要求有人工介入的合理证据，且证据必须在最终答案前给出。
7) 奖励与更新：根据任务完成度、证据可验证性以及越权程度构成标量奖励，Dr.GRPO用奖励更新LoRA策略参数；reward中的权重为人工设定。
8) 评估防作弊：safe success同时要求任务完成、证据、状态可验证且无excess-authority事件，避免策略靠拒绝行动提升安全分。

## 实验如何验证这个想法

任务集为作者编写的2,000个合成任务：1,500训练、300同族验证变体、200整族排除的验证任务，共500个验证任务；验证又分为206任务的routine子集。内部评估共2,896条episodes，276普通任务各4代、224安全重任务各8代。基线为同一基础模型、相同prompt与broker但未训练的base policy；主策略为三粒种子中选出的Seed 1。在routine 206任务集上，Seed 1 safe success为97.63%，base为61.65%（full prompt）；三粒种子分别为85.98%、97.63%、86.29%。在完整500任务验证集上，Seed 1较base多出988个safe episodes、少109个成功越权事件，任务成功率升至99.27%。整族排除的200任务上Seed 1为1,（具体数值未在当前证据中恢复）/1,020，base为689/1,020；未见过的MCP族上为440/440对220/440；Seed 1无exact-lure或forbidden-read尝试，base各有79与52次。外部基准中，MetaTool accuracy由base （具体数值未在当前证据中恢复）%升至Seed 1 83.6%（+1.7pp，p=4.55e-4）；FORTIS T2在两策略均可解析的1,250项上over-privilege由43.28%降至40.72%（p=2.11e-5）；FORTIS T1精确最小技能提升2%、over-privilege减少1.67%，总安全率提升p=（具体数值未在当前证据中恢复）。ToolPrivBench在default prompt下两策略几乎不可分，但privilege-aware prompt对Seed 1降低over-privilege更多。另有400-step continuation实验，在50任务验证集（400 episodes）上safe success由271/400升至362/400，ToolPrivBench over-privilege由245/544降至207/544（45.04%→38.05%，p=3.7e-5）。

## 实验设计

实验通过四类设计隔离效应。1) 同条件对照：base与trained接收完全相同的system prompt、工具清单、broker系统和确定性验证器，因此安全提升被归因于RL引入的最小权限行为而非环境差异。2) 数据划分：300同族验证变体改变词汇、内容、答案字段与模板但沿用训练家族结构，用于防奖励黑客；200整族排除任务引入新家族（fake external reads、log/data transforms、reserved least-privilege choices、新MCP messaging schemas），测试向新任务结构泛化；所有任务仍共享同一broker/sandbox/verifier约定。3) Prompt ablation：固定206任务、1,648 episodes每策略每提示，比较full prompt、去掉least-privilege措辞、one-line prompt三种条件；trained policy只下降0.24pp而base下降3.70pp，说明学习到的行为不是对提示模板的依赖。4) 外部基准与统计：MetaTool、FORTIS、ToolPrivBench提供训练外任务分布及确定性匹配场景，用one-sided paired McNemar tests；FORTIS T2只比较两策略都可解析的1,250项，避免输出有效性差异污染；ToolPrivBench作为contamination-free case study，其200个corrective任务经过关键词匹配与作者规范检查确保不是直接采样验证集，且阶段评审为事后补充而非初始计划。

## 应该怎样解读，而不是过度宣传

内部结果表明训练确实把“正确但不是最小权限”的行为改掉了：Seed 1在500任务集上safe success大幅超过base，且任务成功率99.27%说明提升并非源于拒绝行动；整族排除集上的大幅提升表明一定程度的跨任务结构泛化。Prompt ablation说明当任务界面与训练环境类似时，最小权限行为已被内化而非仅靠提示触发。外部结果则更微妙：MetaTool准确率不降反升，说明训练未损害通用工具选择能力；FORTIS共享可解析样本上over-privilege下降，说明在可比较任务上权威选择更好；但ToolPrivBench默认提示下两策略几乎不可分，仅当给出privilege-aware指令时trained policy才更明显受益，说明在不熟悉的接口或任务环境下，训练行为仍依赖明确提示，外部泛化并不均匀。continuation实验显示针对ToolPrivBench风格任务的额外400步训练可显著降低其over-privilege且保持其他基准能力，说明框架可迁移到新任务族，但该实验从事后Seed 1继续训练，不能当作无偏的泛化证明。总体结论应限定在合成、有界、由确定性验证器支撑的环境内；作者也明确表示训练不能提供强制保证或确定性fail-safe，因此不能据此宣称生产环境安全。

## 局限

作者明确列出的限制包括：任务大多是结构化家族生成、模式清晰，虽然做了整族排除和模板组检查，但不能证明在无约束生产仓库或服务上的表现；六维风险向量的维度和sufficient envelopes编码了可能不完全正确的判断；只用了Qwen3.5-4B一个模型和一个adapter家族；奖励函数权重为人工选择且未系统调参。多个证据还指向任务多样性不足：Step 500已包含98%的内部能力提升，但ToolPrivBench上的外部提升较弱，trained policy在部分failure-escalation族上回退，默认提示下与base统计不可分，作者认为RL主要改变模型已能生成的行为选择而非创造新行为。训练稳定性方面，三粒种子中两粒出现对部分未见过MCP族的malformed argument不稳定，作者建议cold-start SFT。continuation实验从事后Seed 1继续训练，动机是post-hoc，不能作为无偏泛化证据。谨慎推断：我们在解读外部基准时应区分“能力保持”和“通用最小权限推理”，现有证据支持前者强于后者；也不能把安全率提升推广到未覆盖的危险动作类别或真实系统。

## 复现线索

根据论文证据，复现清单至少包含：1) 使用Qwen3.5-4B并通过LoRA适配，优化器为direct Dr.GRPO，cold-start采用详细least-privilege提示而非SFT；奖励函数权重为论文作者手工设定，但具体数值、学习率、batch、LoRA rank、GAE、KL系数等未在证据块中出现，标记为unknown。2) 构建终端与MCP的可执行broker：对每个动作做pre-audit、确定性计算intended authority、选择执行模式、执行后记录实际效果；六维风险向量按pre/post逐维最大值累计。3) 编写2,000个任务（1,500训练、300同族验证、200整族排除），每个任务带reference oracle与sufficient-authority envelope；验证verifier需检查exact answers、hidden tests、required output files、targeted test results、精确MCP state、evidence paths、required writes与拒绝额外写入。4) 评估协议：500任务验证集共2,（具体数值未在当前证据中恢复） episodes（普通任务4代、安全重任务8代），routine子集206任务×8代；safe success要求完成、证据、可验证且无excess-authority事件。5) 外部评测：MetaTool 1,000项、FORTIS T1 600项、T2 1,543项、ToolPrivBench 544场景；FORTIS T2需限定在两策略均可解析的1,250项。6) Prompt ablation在三提示条件下各1,（具体数值未在当前证据中恢复） episodes。复现所需的具体奖励公式、风险向量权重、任务模板生成器、continuation学习率与调度均未知，需要参考论文正文或代码仓库。
