# Task-Conditioned Least-Privilege Learning for Executable Terminal and MCP Agents

> 证据等级：full_text_text。不保存论文原文；请通过来源链接核查。

## 一分钟总结

本文提出面向可执行终端与 MCP 智能体的任务条件化最小权限学习方法，利用 broker、任务模式、后动作校验器与超额权限计算相互分离的模块化框架，按任务需求动态收紧权限边界，抑制读取无关记录、误编辑目标等副作用。

## 问题

工具型智能体虽能顺利完成从 MCP 工具调用到文件编辑的各类任务，却仍会造成非预期副作用并违背用户请求，例如读取无关记录、编辑目标；这表明仅追求任务完成度不足，必须把“完成任务”与“最小必要权限”同时纳入约束。

## 方法

方法由四类组件构成：broker 负责预动作判断与证据项要求；任务模式描述任务所需行为和权限；后动作校验器在动作后核验实际行为；超额权限计算基于风险向量（如写超额）对动作分类。对仅需读 bug.txt 并提补丁的提案任务，写被视为超额；对跨服务任务，则需提升外部访问与写入的充足权限包络，并加强后动作校验。各组件解耦使框架可针对不同任务灵活配置。

## 实验与结果

证据只给出任务与评测设计：作者编写了 2000 个独立任务，覆盖定向阅读、代码修改、测试选择、恢复、类别升级、提示注入克制、秘密诱饵、外部读取、MCP 状态变更与多工具工作流；每个任务带参考 oracle 与计算出的充足权限包络。校验共 500 个任务：300 个族内变体用于防止奖励黑客并检验训练收益，200 个排除族任务用于检验最小权限是否迁移到新任务结构。文中未见基线、指标或数值结果。

## 局限与阅读边界

作者承认任务多为结构化家族合成的，即使做整族留出与模板检验，也不能代表无约束生产仓库或服务的表现；权限维度、权重与充足包络编码的判断可能不完全正确，仅靠每任务风险档案说明缓解。研究只使用一个 4B 模型和一个适配器家族，但作者引用以往研究推测表示层相似性可能跨模型族和规模迁移（文献 24）。

## 复现线索

复现要点：1) 实现 broker、任务模式、后动作校验器和超额权限计算四组件；2) 为每个任务定义参考 oracle 和充足权限包络；3) 构建 2000 个任务的目录，其中 300 个同族校验、200 个排除族校验，共计 500 校验任务；4) 覆盖定向读取、代码修改、提示注入克制、外部读取、MCP 状态变更等课程；5) 用后动作校验与风险向量写超额分量评估越权。训练算法、超参数与具体工具权限配置在证据中缺失，需查阅原文。

## 核心直觉

核心直觉是权限应是任务条件化的：不同任务需要不同的最小权限包络。框架把 broker、任务模式、后动作校验器和超额权限计算拆开，使只读型提案任务（如读 bug 报告并提补丁）中写操作被判定为超额，而需跨服务读写、从 GitHub 类服务经 MCP 读取并写入数据库的任务则获得更高的外部访问与写入权限包络，并更依赖后动作校验与风险向量的写超额分量，从而灵活适配任务差异。

## 工作流程（一步一步）

1) 依据任务模式定义任务意图与权限边界；2) 预动作 broker 检查证据项并计算最小充足权限包络，拦截越权动作；3) 智能体在包络内选择并执行允许的动作；4) 后动作校验器核对实际行为是否符合任务要求；5) 超额权限计算按风险向量（如写超额）对执行结果分类，并据此调整策略。只读提案任务中不执行变更动作；跨服务任务则需提升外部访问与写入包络并强化后动作校验，从而实现输入任务到受限执行再到越权评估的闭环。

## 实验设计

该设计通过双分区隔离效应：300 个同族校验主要防止显式奖励黑客、验证训练收益；200 个来自训练池外任务族的校验用于检验在相同 broker 终端与 MCP 环境下学得的最小权限能否泛化到新结构。课程覆盖多种风险场景，并以参考 oracle 和计算出的充足权限包络作为对照基准，以区分任务完成度与权限超额。未报告消融或对照方法。

## 结果如何解读

当前证据不支持任何数值结论：没有给出成功率、副作用率或基线对比。可解释的是设计意图：同族校验负责确认训练收益且不易被奖励黑客利用；异族校验负责检验最小权限策略能否迁移到未见任务结构。若后续有结果，应分别比较两分区表现以判断学到的权限约束是记忆训练族还是真正泛化。
