# Task-Conditioned Least-Privilege Learning for Executable Terminal and MCP Agents

> 证据等级：full_text_text。不保存论文原文；请通过来源链接核查。

## 一句话先说清楚

本文针对终端与 MCP 工具型智能体在完成任务时产生的超额权限行为，提出任务条件化最小权限学习框架。核心做法是由不可见的环境代理（broker）在动作前后对六维风险向量进行审计，为每个任务设定充分权限包络，并用直接 Dr.GRPO 在 1500 个可执行任务上对 Qwen3.5-4B 做 LoRA 微调，使模型学会在保持任务成功与证据可验证的前提下不越权。内部验证显示安全成功率和跨任务族泛化均显著提升，外部 MetaTool、FORTIS 与 ToolPrivBench 上也有改善；论文同时强调该训练不能替代权限门等确定性系统控制。

## 背景：作者发现了什么问题

设想用户请智能体读取 bug.txt 并给出补丁建议：模型可能顺带读取无关记录、修改任务范围之外的目标、选择权限更高或风险更大的工具，甚至触发动态执行、越过环境边界，最终虽然给出了正确回答，动作轨迹却已越权，并可能构成权限提升。这类行为被定义为任务相对超额权限错误。仅以最终答案正确性为评价指标的测试无法发现它，因为错误发生在动作过程而非结果之中。现有防御主要采用事后拦截：权限门在模型提出或执行动作后阻断被识别为高风险的动作类别，但功能等价的状态变更可能经由文件编辑等未被同类门控覆盖的路径绕过；静态权限门还可能在授予无关敏感访问的同时遗漏执行链真正需要的权限。因此需要将最小权限本身纳入训练目标，使模型在动作选择阶段就学会只行使足以完成任务并留下可验证证据的权限，同时避免超额权限。当前缺口是缺少一种可计算的、相对任务定义的权限度量以及配套的可执行训练环境，本文正是围绕该缺口展开。

## 论文真正要解决的问题

能否通过强化学习让工具型智能体在真实可执行终端与 MCP 环境中同时满足两个要求：一是可靠完成任务并产生可验证的证据，二是在每个动作上都不超出该任务所需的充分权限包络？本文把这两个要求合并为安全成功率这一指标，并以此作为训练与评估的核心目标，尝试回答最小权限行为能否被内化为模型自身能力，而非仅仅依赖提示词触发。

## 核心想法：把问题变成可计算目标

核心直觉是：最小权限不能由一个固定规则或静态门给出，而必须相对于具体任务定义。同一个写操作在某些任务中是必需的，在另一些任务中就是越权。为此，模型虽然看到完整的工具清单，但真正决定动作能否执行的是一个模型不可见的环境代理（broker）。代理对每个提出的动作做确定性解析，计算其意图权限与执行风险，选择执行方式，并在执行后再记录实际效果。作者定义了一个六维风险向量，包含状态突变、动态执行、是否触及环境边界、未授权敏感数据访问、影响范围是否过宽、以及状态是否在任务结束后仍然持久存在等维度；动作轨迹的风险向量取每一步前后评估的逐维最大值。每个任务预先有一个充分权限包络，只有超出该包络的行为才被惩罚。与静态门不同，这里的边界是任务相对的，并且由环境在执行层面强制计算；与只给提示的基线相比，训练目标是让模型在动作选择阶段就内化最小权限，而不是在动作发生后依赖外部拦截。训练使用直接 Dr.GRPO 对 Qwen3.5-4B 做 LoRA 微调，奖励同时要求任务完成、证据充分、状态可验证以及不存在超额权限事件。这样设计可以避免一个常见陷阱：如果只惩罚越权，模型会倾向于消极不作为；把任务成功纳入同一指标后，模型必须学会在够用的权限下完成任务。

## 方法如何落地

方法由四个核心组件构成。第一，任务与权限包络：每个任务都带有参考预言机和计算好的充分权限包络；任务类型包括定向读取、代码修改、测试选择、恢复、分类升级、提示注入抑制、秘密诱饵、外部读取、精确 MCP 状态修改和多工具工作流。第二，环境代理（broker）：模型只看到完整工具清单；代理在动作执行前解析动作、确定性计算意图权限、评估执行风险、选择执行模式并做预审计，动作执行后记录实际效果；对权限的度量是六维风险向量，动作前后的风险取逐维最大值，轨迹风险记录所有动作中每个维度达到的最大值。第三，验证器：验收条件包括精确答案、隐藏测试、要求输出的文件、目标测试结果、精确 MCP 状态、证据路径、必需写入，以及拒绝额外写入；提案类任务禁止环境变更并对变更给予惩罚，升级类任务要求有充分证据的人工介入理由，证据是终端门控的，即最终答案之后发生的读取不能为之前的答案提供证据。第四，训练目标：使用 LoRA 与直接 Dr.GRPO，对 Qwen3.5-4B 在 1500 个可执行任务上训练；奖励由安全成功率驱动，同时要求任务完成、证据、状态可验证性和不存在超额权限事件。基线与训练策略使用完全相同的系统提示、工具清单、代理系统和确定性验证器，因而差异主要来自策略对最小权限规则的理解与应用。框架的越权计算与验证代理也可嵌入其他奖励函数与算法，不限于 Dr.GRPO；代理、任务模式、动作后验证器和越权计算相互分离，因而可适配不同任务，提案类只读任务与多工具跨服务任务拥有不同的充分权限包络与验证侧重。

## 工作流程（一步一步）

1) 输入任务：每个任务附带参考预言机与充分权限包络，模型看到完整工具清单以及环境说明。2) 策略选择动作：模型输出终端命令或 MCP 工具调用。3) 代理预审计：不可见的 broker 解析动作，确定性计算意图权限，评估六维风险，选取执行模式；若属于提案类任务，则禁止环境变更并把变更作为惩罚。4) 执行：动作被发送到终端或 MCP 沙箱服务执行，代理记录实际产生的效果与状态变化。5) 动作后评估：对执行后的状态再次做风险计算，将前后风险取逐维最大值，并用该最大值更新轨迹风险向量，记录各维度在整个任务期间达到的最大值。6) 自动验证：验证器检查最终答案、隐藏测试、输出文件、目标测试结果、精确 MCP 状态、证据路径、必需写入，并拒绝额外写入；对升级类任务检查人工介入理由是否充分，证据采用终端门控，最终答案之后的读取不能追认答案。7) 奖励计算：根据任务完成、证据、可验证性以及是否出现超额权限事件计算奖励，供 Dr.GRPO 做策略更新。8) 参数更新：通过 LoRA 更新 Qwen3.5-4B，并在每步之后重复上述循环。9) 审计输出：最终得到逐动作预/后审计记录以及六维轨迹风险向量，用于训练监控、评估和事后分析。在一次完整轨迹中，单个动作可能提升某一维度的风险值，因此轨迹风险向量必须保留历史最高值，而不是只看最终状态，这使得即使最后状态正确，中间任何越权动作仍然会被记录和惩罚。

## 实验如何验证这个想法

任务构建：作者编写了 2000 个任务，其中 1500 个训练任务、300 个组内变体验证任务、200 个未训练任务族的持有验证任务；行为组包括定向读取、代码修改与测试、恢复与升级、对抗性约束、MCP 与多工具等，另有未见面任务族用于泛化测试。评估设置：完整内部验证集为 500 个任务，共 2896 个回合（276 个普通任务各 4 代、224 个安全重点任务各 8 代）；例行检查使用 206 任务子集，每任务 8 代；外部评估使用全部 544 个 ToolPrivBench 场景、FORTIS 两个任务分别 600 与 1543 项，以及 MetaTool 固定 1000 项子集。基线是与训练策略使用相同提示、工具清单、代理与确定性验证器的未训练基础策略。主要指标是安全成功率，即同时满足任务完成、证据、可验证状态与无超额权限事件。内部结果：三颗种子在 206 任务例行集上的安全成功率为 （具体数值未在当前证据中恢复）%、97.63%、86.29%，选定最稳定的 Seed 1；在完整 500 任务验证集上，Seed 1 比基础策略多出 988 个安全回合，少 109 次超额权限事件，任务成功率 99.27%。未训练任务族分区上 Seed 1 为 1020/1020 安全回合而基础为 689/1020；未见 MCP 任务族为 440/440 对比 220/440。外部结果：MetaTool 准确率由基础 81.9% 升到 83.6%（p=4.55×10⁻⁴）；FORTIS T2 可解析输出中越权率由 43.28% 降至 40.72%（p=2.11×10⁻⁵）；FORTIS T1 相对基础策略在精确最小技能上提高 2%、越权率下降 1.67%（总安全率 p=（具体数值未在当前证据中恢复））。续训研究：从 Seed 1 出发做 400 步 ToolPrivBench 风格矫正续训后，50 任务持有集安全成功率从 67.75% 升到 90.50%，ToolPrivBench 越权率从 45.04% 降到 38.05%（p=（具体数值未在当前证据中恢复）×10⁻⁵）。

## 实验设计

实验设计通过多个对照组与消融隔离训练效应。第一，基线与训练策略使用完全相同的系统提示、工具清单、代理、沙箱与确定性验证器，因此安全成功率差异主要来自策略对最小权限规则的理解与应用能力。第二，提示消融：在固定 206 任务例行集上对每个提示-策略组合做 1648 回合；完整提示下基础与 Seed 1 分别为 61.65% 与 97.63%，去掉最小权限措辞后为 60.92% 与 97.63%，缩短为一行提示后为 57.95% 与 （具体数值未在当前证据中恢复）；训练策略仅下降 0.24 个百分点而基础下降 3.70 个百分点，用以检验行为是否依赖提示。第三，任务分区：300 个组内变体改变词汇、内容、答案字段与模板，防止奖励黑客；200 个未训练任务族引入全新行为族与 MCP 消息模式，检验跨任务族泛化。第四，检查点分析：比较 500、（具体数值未在当前证据中恢复）0、1500 步检查点，显示第 500 步已包含 98% 的改进（581/593），后段只修正个位数任务，说明早期即饱和并暴露任务多样性不足。第五，外部基准：MetaTool、FORTIS、ToolPrivBench 均为独立于训练环境的确定性评估；FORTIS T2 只比较两种策略都能解析的 1250 项，避免输出有效性差异干扰；ToolPrivBench 还区分无提示与特权感知提示条件。第六，续训研究设计 200 个 ToolPrivBench 风格矫正任务加 200 个原任务排练任务，并做关键词匹配防直接污染，检验框架迁移到新任务域的能力。

## 应该怎样解读，而不是过度宣传

内部结果表明训练确实降低了超额权限：在 500 任务验证集上安全回合增加 988 次、超额权限事件减少 109 次，而任务成功率仍达 99.27%，说明提升并非来自消极不作为。作者在讨论中指出，在相同规则与环境下两者安全成功率相差 34.12 个百分点，因此至少部分反映策略对最小权限规则的理解与应用能力。提示消融进一步显示训练后的策略在三种提示条件下几乎稳定（97.63% 到 （具体数值未在当前证据中恢复）），而基础策略随提示缩短下降 3.70 个百分点，说明最小权限行为在一定程度上被内化为模型能力；不过内部基准与训练环境同构，不能据此推断任意新环境中的表现。外部结果中，MetaTool 准确率提升 1.7 个百分点、FORTIS T2 共享可解析项上的越权率下降 2.56 个百分点，说明训练没有损害通用工具选择能力，甚至略有改善；但 FORTIS T2 只能比较 1250/1543 个双方都能解析的项，基础策略有大量空输出或不可解析输出，因此该对比并不能代表完整任务分布。ToolPrivBench 原始 Seed 1 在无提示条件下与基础策略几乎不可区分，且部分失败升级任务族出现回退，说明跨接口泛化并不均匀；矫正续训才使越权率下降 6.99 个百分点。作者明确指出该训练不能提供执行保证或确定性失效保护，学习到的策略仍应部署在权限分离系统与权限门之后；因此本文的证据只支持在合成、有界环境中减少不必要权限请求这一结论，不能推广为生产安全保证。

## 局限

作者明确承认的局限包括：任务大多是合成生成的，来自结构清晰、分组与测试模式预先定义的任务族，因此即使有全族持有与模板组检查，也不能建立对无限制生产仓库或服务的性能。风险向量各维度、权重与充分权限包络编码了可能并不完全正确的人工判断。训练只使用了一个 4B 模型与一个适配器家族。训练中第 500 步已包含 98% 的内部安全成功能力增益，后段停滞，提示任务多样性不足；原始训练在 ToolPrivBench 无提示条件下与基础策略统计上不可区分，且在某些失败升级任务族上退化，说明外部泛化不均。续训是从已选定的 Seed 1 出发，且动因是事后的，并非无偏泛化检验。此外两粒种子在未见 MCP 任务族上出现畸形参数的不稳定，作者推测 SFT 冷启动可以缓解。奖励函数的权重是人工设定而非学习的，作者未测试大幅变化的权重组合。可以谨慎推断的是：框架的收益在训练分布及其邻近任务族上稳健，但对完全不同的接口与无提示环境，效应显著减弱；这些是结果解读层面的推断，而非作者明确声明。

## 复现线索

复现清单：1) 模型：Qwen3.5-4B，用 LoRA 微调，训练算法为直接 Dr.GRPO。2) 环境：提供终端与 MCP 沙箱，代理在动作前解析、预审计、计算六维风险向量并选择执行模式，动作后记录实际效果。3) 任务：构建具有参考预言机与充分权限包络的任务集，至少覆盖 1500 训练任务、300 组内验证任务、200 未训练任务族，行为组包括定向读取、代码修改、恢复升级、对抗性约束、MCP 多工具等。4) 验证器：检查精确答案、隐藏测试、输出文件、目标测试、精确 MCP 状态、证据路径、必需写入并拒绝额外写入，证据实行终端门控。5) 训练：在 1500 任务课程上训练，并监控 206 任务例行集与 500 任务验证集。6) 评估：内部评估使用 500 任务 2896 回合、206 任务例行集、200 全族持有、未见 MCP 族；外部使用 MetaTool 1000 项、FORTIS T1 600 项与 T2 1543 项、ToolPrivBench 544 场景。7) 提示条件：完整提示、去掉最小权限措辞、一行提示三种条件分别评估。作者还披露，仓库中大部分代码与任务编写由 Codex 和 Claude Code 在人工监督下合成生成，并在论文写作中使用生成式 AI 工具辅助校对。未知细节包括具体学习率、LoRA rank、批次大小、奖励函数中各分量的数值权重、Dr.GRPO 超参数与硬件配置；表 II/III 的逐行数字也未在可解析文本中完整呈现，复现时需自行取定并报告。
