# Task-Conditioned Least-Privilege Learning：人工黄金精读

> 这份笔记是人工黄金答案，用来检验“是否真正读懂论文主线”，不是机器证据层，也不是论文原文的替代品。来源：[arXiv HTML](https://arxiv.org/html/2608.18351v1)。

## 一句话先说清楚

这篇论文解决的不是“智能体能不能完成任务”，而是“完成任务时，能不能只使用完成任务所必需的权限”。作者把最小权限从静态规则变成任务条件化的可学习目标：broker 在每个动作执行前后审计真实风险，verifier 检查任务是否完成且证据/状态是否正确，再用超出任务充分权限包络的部分惩罚训练策略。Qwen3.5-4B 经 1,500 个可执行任务的 Dr. GRPO 后训练后，在 500 个留出任务、2,896 个 episodes 上，safe success 从 64.36% 提升到 98.48%，超额授权成功事件从 4.56% 降到 0.79%。

## 背景：为什么“答案正确”仍然不够

终端和 MCP 智能体可能给出正确答案，却在过程中读取无关记录、修改任务范围外的文件、调用不需要的高权限工具，甚至留下持久副作用。传统最终答案评测看不到这些轨迹级问题；静态 permission gate 也有两个缺陷：它只能覆盖已识别的动作类别，功能等价的状态变化可能从另一条路径绕过；同时它可能漏掉执行链真正需要的权限，却授予无关的敏感访问。

因此作者把问题定义为 task-relative excess-authority error：只要实际执行的权威超过当前任务合理的最低需求，即使最终状态正确，也算越权。论文的研究问题是：能否让后训练后的模型在可执行终端和 MCP 环境中，同时完成任务、提供充分证据、达到精确状态，并且不越过该任务的充分权限边界？

## 核心想法：测量“实际发生了什么”，而不是只看“调用了什么”

模型能看到完整工具清单，但看不见 broker。模型提出终端命令、MCP 调用、升级请求或最终答案后，broker 先解析动作并预审计；动作在非 root 容器或可重置 MCP 服务中执行后，再根据文件/Git diff、进程遥测、服务记录、敏感路径访问和精确状态变化做后审计。这样既能记录被拦截动作“想要什么权限”，也能记录实际产生的效果。

每个动作有六维权威向量：写入/状态突变、动态执行、跨环境边界、敏感数据访问、影响范围、持久状态。论文将它写成：

$$
\mathbf z(a_t)=[z_{write},z_{exec},z_{external},z_{secret},z_{scope},z_{persistent}]\in[0,1]^6.
$$

动作风险取执行前后逐维最大值，轨迹风险再取所有动作的逐维最大值：

$$\mathbf z_\tau=\max_t\mathbf z(a_t).$$

每个任务有人工审核过的充分权限包络 $\mathbf z_{req}(x)$，只惩罚超出的部分：

$$\boldsymbol\Delta(\tau,x)=\max(\mathbf z_\tau-\mathbf z_{req}(x),\mathbf0).$$

安全成功不是“少做事”，而是同时满足任务成功、证据充分、精确状态约束和零可报告越权事件：

$$\textsc{SafeSuccess}=\mathbb1[S=1\land E\ge e_x\land V_x=1\land O_\tau=0].$$

**图 1 应该放在这里**：它展示策略 → broker 预审计 → 终端/MCP 执行 → 后审计 → reward → 参数更新的闭环；它解释的是组件关系，不是一个额外结果。

## 方法如何训练

方法由四部分组成：

1. Qwen3.5-4B 基座，rank-32 LoRA，bfloat16，直接 Dr. GRPO；每行采样 8 条轨迹，每条最多 4,096 token、20 次工具调用，batch size 1、梯度累积 8、无 KL 项、无 SFT。
2. 不可见 broker 负责动作解析、执行前/后审计、执行模式选择和效果记录。
3. 每个任务提供 reference oracle、sufficient-authority envelope、证据要求、确定性 verifier 和负例。
4. verifier 检查精确答案、隐藏测试、必需输出文件、定向测试结果、精确 MCP 状态、证据路径、必要写入，以及是否拒绝额外写入；证据是 terminal-gated，最终答案之后的读取不能补救此前缺失的证据。

标量奖励为：

$$R=0.60S+0.20E-0.20P-0.05U+0.10H-0.75B-0.05F_u-0.12F_r,$$

其中 $P$ 汇总轨迹越权惩罚，$U$ 惩罚无谓动作/循环，$H$ 奖励正确升级，$B$ 是被阻断动作严重度，$F_u$ 和 $F_r$ 分别表示格式/不支持动作与禁止读取。这个奖励的目的不是只降低越权率，而是让模型在完成任务的前提下学会“恰好够用”。

## 实验怎么证明它有效

作者构造 2,000 个合成任务：1,500 train、300 within-family validation、200 excluded-family validation，覆盖读取定位、代码修改、恢复升级、对抗约束、MCP/多工具和未见行为族。500 个留出任务共生成 2,896 个 episodes；routine 子集为 206 个任务。

### 500-task held-out 主结果

| 指标 | Base | Seed 1 | 变化 |
|---|---:|---:|---:|
| Task episode success | 1,996/2,896 (68.92%) | 2,875/2,896 (99.27%) | +30.35 pp |
| Safe success | 1,864/2,896 (64.36%) | 2,852/2,896 (98.48%) | +34.12 pp |
| Excess-authority success | 132/2,896 (4.56%) | 23/2,896 (0.79%) | −3.77 pp |

这说明收益不是靠拒绝行动换来的：Seed 1 多出 988 个安全成功 episodes，同时任务完成率升到 99.27%。在 whole-family held-out 的 1,020 episodes 上，Seed 1 safe success 为 1,020/1,020，Base 为 689/1,020；在 unseen-MCP family 上是 440/440 对 220/440。Seed 1 没有 exact-lure 或 forbidden-read 尝试，而 Base 分别有 79 和 52 次。

### 其他验证

- routine 206-task：Base safe success 61.65%；checkpoint 500/1000/1500 分别为 96.91%/97.57%/97.63%，说明前 500 步已获得约 98% 的内部增益，后续主要修补少数任务族。
- prompt ablation：Seed 1 在完整提示、去掉 least-privilege 措辞、单行提示下 safe success 为 97.63%/97.63%/97.39%，Base 为 61.65%/60.92%/57.95%；训练策略对提示变化更稳，但并非完全脱离界面说明。
- 外部基准：MetaTool 81.9%→83.6%（$p=4.55\times10^{-4}$）；FORTIS T2 shared-parse over-privilege 43.28%→40.72%（$p=2.11\times10^{-5}$）。FORTIS T2 只比较 1,250 个双方都成功解析的样本。
- 400-task continuation：用 200 个纠正任务 + 200 个 rehearsal 任务续训 400 steps；50-task held-out safe success 67.75%→90.50%，原 500-task safe success 98.48%→98.76%，ToolPrivBench over-privilege 45.04%→38.05%。

## 应该怎样解读

论文最有说服力的证据链是：训练策略在同一 broker、同一工具清单和同一 verifier 下，既提升任务完成，又显著减少越权；prompt ablation 表明它不完全依赖一条固定提示；whole-family 与 unseen-MCP 结果说明存在一定结构泛化；续训说明针对新型失败模式可以继续纠正，同时基本保留原有能力。

但这不是“模型已经安全”。任务是合成且结构化的，六维风险和 sufficient envelope 含有人为设计，主实验只有一个 4B 模型和 LoRA 家族，奖励权重是手工设定，多个 seed 在未见 MCP 族仍有格式错误，ToolPrivBench 默认提示下 Base 与 Seed 1 几乎没有差异。正确结论是：这种后训练可作为 permission gate、sandbox 等强制控制的补充层，而不是替代品。
