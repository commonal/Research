# 自适应教学式精读：两篇异构论文泛化对比

日期：2026-08-24

## 验证问题

在不使用论文专属 prompt、人工改正文或生产默认策略的前提下，同一条通用阅读路线能否同时处理：

1. 公式和方法机制密集的架构论文；
2. 没有核心公式、以评测设计和实验结果为主的 benchmark 论文。

通用路线为：完整有序论文材料 → PaperModel → 语义素材规划 → 公式/表格证据邻域 → 选择性视觉读取 → 结构化中文 Writer → 有界修复 → 盲读验收 → 确定性渲染。

## 实际样本

| 论文 | 结构特点 | 输入材料 | 最终状态 |
| --- | --- | --- | --- |
| Mamba (2312.00752v2) | 方法与公式密集，包含架构图、公式和跨任务结果表 | 322 blocks，14 个公式、11 个图、13 个表 | `generalization_passed` |
| PaperBench (2504.01848v3) | benchmark/评测设计，无核心公式，依赖流程图、rubric 与结果表 | 170 blocks，0 个公式、3 个图、6 个表 | `generalization_passed`（用户阅读认可；v4 深度契约复核通过） |

## 已验证的通用能力

- **材料顺序和引用边界**：模型只使用程序生成的稳定 handle，不再生成或猜测 block ID。
- **不同材料类型自适应**：Mamba 正常选择并解释 3 个公式；PaperBench 在发现真实公式数为 0 后，错误的公式规划被安全降级，没有伪造公式。
- **选择性视觉读取**：两篇论文都只将 3 张高解释价值图片送入正文，而不是全量展示图片。
- **公式、表格与正文共同规划**：Mamba 最终自然嵌入 3 个公式、3 个图和 3 个表；PaperBench 嵌入 3 个图和 3 个表。
- **确定性渲染边界**：两篇 HTML 的计划图片、表格和公式均完整呈现，没有临时路径泄漏。
- **事实保留边界**：只有能在所引证据块中直接找到的实体与数字才进入强制保留门禁；规划器产生但证据不支持的 token 被显式降级，而不是强行写入正文。

## 质量结果

### Mamba

- 正文 6,375 字符、8 个主要章节。
- 3 个公式、3 个图、3 个表进入正文。
- 盲读的背景问题、既有方法缺口、核心方案、形式化机制、实验、视觉证据和边界均为 `clear`。
- HTML 完整性检查通过。
- 实际调用：10 次文本调用（包含被替代的检查/修复调用），3 次视觉调用。

结论：通用路线对公式密集型方法论文成立，而且公式和视觉材料确实参与解释，不只是作为附件陈列。

### PaperBench

- 正文 3,589 字符、8 个主要章节。
- 3 个图、3 个表进入正文，未伪造公式。
- 盲读门禁和 HTML 完整性检查均通过。
- 实际调用：8 次文本调用（包含 1 次未采用的分组深化尝试），3 次视觉调用。
- 用户实际阅读后认可当前解释深度；固定长度告警不再作为阻断条件。

与此前用户认可的 PaperBench 教学式笔记相比，旧笔记约 5,361 字符，对 rubric 构造、实验设置、失败分析以及段落过渡讲得更充分。但旧实验包含 PaperBench 专属写作规则，不能作为“同一通用路线”的通过证据。

## 当前架构判定

两类异构论文的通用路线均已通过实际阅读与自动边界检查，可以认为初步泛化成立。

已经验证的是：**通用 PaperModel、素材选择、公式/表格邻域、选择性视觉读取、证据校验和渲染边界可以跨论文结构工作。**

仍不应仅凭这两篇实验切换生产默认策略；正式接入还需要完成目标论文的 B 路线回放和全套回归。

## SectionDepthPlan 后续实验

用户实际阅读后认可 PaperBench 通用版本，因此原先的固定长度告警不再作为质量失败。随后在不覆盖 v2 产物的前提下运行了 `adaptive-generalization-paperbench-v4-depth-ledger`：

- 程序先从 PaperModel 确定性生成 CoverageLedger；
- ledger 包含 29 项不可静默丢弃的论证、实验、关键事实、局限和 inline 素材义务；
- 4 组实验和 6 个 inline 素材均被唯一绑定到章节；
- SectionDepthPlan 不设置目标字数，而是记录 reader state、answer contract、prerequisite bridge、reasoning steps、experiment contract、asset job、transition 和 stop condition；
- Writer、强事实检查、盲读七项和 HTML 图表完整性全部通过；
- 最终正文 3,430 字符，固定长度检查仅作为非阻断观察值，状态为 `generalization_passed`；
- 复用已有图像解释，新增总调用为 3 次文本、0 次视觉。

该实验没有证明“单独增加一次 SectionDepthPlan 模型调用必然让文字更好”：v4 与已认可的 v2 长度和整体可读性接近。它证明的是 CoverageLedger 能把完整性从 prompt 愿望变成可校验状态，SectionDepthPlan 能把章节深度从字数目标改成理解契约。

若进入正式实现，优先把这些契约字段并入 PaperModel 的同一次规划调用，并由确定性 CoverageLedger 校验；只有复杂论文出现未分配义务或跨节依赖冲突时，才额外调用独立的 SectionDepthPlan。这样保留结构保证，又避免每篇论文固定增加一次模型调用。
