# Task-conditioned Least-Privilege Learning for Executable Terminal and MCP Agents

model: deepseek-chat
normalized_blocks: 135
reading_units: 10
llm_calls: 12

## summary

论文针对工具使用型 LLM 代理在终端和 MCP 环境中常见的“超额权限错误”提出任务条件最小权限学习框架。作者认为传统权限门控在模型提出动作后才检查，覆盖面有限且可能被功能等价命令绕过。该框架在动作执行前与执行后各做一次审计，沿六个风险维度度量动作权限；结合任务的“充分权限包络”计算轨迹级超额权限，再通过直接 Dr. GRPO 对 Qwen3.5-4B 做后训练，让模型学会按任务选择所需的最小权限。实验显示，在用 1,500 个任务训练后，选出的 Seed 1 在 2,896 个评估回合上把安全成功率从基线的 64.36% 提升到 98.48%，超额权限事件率从 4.56% 降到 0.79%；外部测试表明一般工具选择能力未受损，且提示消融显示该行为并非依赖提示措辞。

## problem

工具使用型代理能够完成终端命令、MCP 调用、文件编辑等任务，但常常在成功完成目标的同时行使用户未授予或任务并不需要的权限，造成任务相对型超额权限错误，例如读取无关记录、编辑任务范围外的目标、使用具有更高权限或更高风险的工具。传统权限门控主要在模型提出动作之后才拦截，其覆盖面取决于已学习的风险动作类别，功能等价的状态改变或命令可通过文件编辑等未同样被门控的路径绕过；静态门控还可能漏掉执行链真正需要的访问，同时授予任务不需要的敏感访问。论文引用的证据也显示，部署中的 Claude Code auto mode 在 52 个“过分积极”动作上仍有较高假阴性率，外部测试甚至发现大量动作落在分类器范围之外。因此，仅靠权限门控不足以控制系统性的超额权限问题。

## research_question

能否通过后训练让一个 4B 参数模型学会“任务条件化权限选择”，即在可执行的终端与 MCP 环境中，只使用任务要求的充分且适当的权限，从而在显著降低超额权限错误的同时保持甚至改善任务完成能力？

## core_idea

最小权限应当是任务相对且可测量的。论文把每次动作表示为一个六维权限向量，分量分别对应写入/状态变更、动态执行、触及环境边界、未授权敏感数据访问、作用范围宽泛、以及超出本次操作的持久状态。一条轨迹的权限向量取所有动作各维度的分量最大值；每个任务预先设置经过审核的“充分权限包络”z_req(x)，超额权限向量为 Δ(τ,x)=max(z_τ−z_req(x),0)，只在超出任务需要的维度上产生惩罚。安全成功定义为任务成功、证据充分、任务特定状态约束满足且无报告性超额权限事件的合取；报告性超额权限事件区分“模型试图做什么”和“环境实际允许了什么”，因此被阻断的命令仍会被记录为越权请求。最终奖励采用非势函数形式 R=0.60S+0.20E−0.20P−0.05U+0.10H−0.75B−0.05F_u−0.12F_r，刻意给过权限轨迹增加“摩擦”，使模型偏好低权限的最小充分路径，而不是仅仅优化任务结果。

## method

框架是可迁移的模块化系统，核心包括任务相对权限分类、六维风险向量、带前后执行审计的 brokered 终端/MCP 环境、充分权限包络和确定性验证器。每个轨迹首先由宿主 broker 做预执行审计：解析命令族、标志、路径、重定向、组合方式、工具身份和参数广度，计算“意图中的权限”并评估执行风险；随后在非 root 容器或可重置 MCP 服务中执行以获得真实效果；后执行审计利用文件/Git diff、进程遥测、服务记录、敏感路径访问和精确状态变化来观察实际影响。最终动作权限取预审计与后审计向量的分量最大值，这样即使命令被阻断也能记录模型曾请求的越权权限。任务端为每个任务配有参考 oracle、充分权限包络、证据要求和确定性验证器；verifier 检查精确答案、隐藏测试、必需输出文件、定向测试结果、精确 MCP 状态、证据路径、必需写入和拒绝额外写入。训练使用 Qwen3.5-4B 和 rank 32 LoRA，结合直接 Dr. GRPO 在 1,500 个任务的可执行课程上优化；框架的权限计算与验证 broker 也可嵌入其他奖励函数和算法，不限于 Dr.GRPO。

## workflow

整体流程为：(1) 构建 2,000 任务目录，划分为 1,500 个训练任务、300 个族内验证任务和 200 个族外验证任务，并为每个任务定义充分权限包络、证据要求、oracle 和确定性 verifier；(2) 在 brokered 终端/MCP 环境中执行策略轨迹，预审计与后审计共同产生六维权限向量；(3) 计算轨迹级超额权限和标量奖励；(4) 用直接 Dr. GRPO 以每行 8 条轨迹的采样方式更新 LoRA 参数；(5) 在 500 任务留出集、206 任务 routine 集上做内部评估，完成提示消融，并在 MetaTool、FORTIS、ToolPrivBench 上做外部评估；(6) 用 200 个 ToolPrivBench-informed 纠正任务加 200 个原始训练任务做 400 步 continuation，检验框架迁移到新任务域的能力。

## experiments

内部 500 任务留出集上，基线与 Seed 1 在相同系统提示、工具清单、broker 和确定性 verifier 下比较：任务回合成功率从 68.92% 升至 99.27%（+30.35 pp），安全成功率从 64.36% 升至 98.48%（+34.12 pp），超额权限事件从 132（4.56%）降至 23（0.79%）。三个种子中，Seed 1 最稳定，routine 206 任务集安全成功率为 97.63%，而 Seed 0 和 Seed 2 分别为 85.98% 和 86.29%。检查点结果显示，checkpoint 500 已达到 96.91% 安全成功率，checkpoint 1000 为 97.57%，checkpoint 1500 为 97.63%，即 98% 的总改进已在早期出现。提示消融中，去掉最小权限措辞后 Seed 1 仍为 97.63%，一行短提示下为 97.39%，仅下降 0.24 个百分点；基线则在三种提示下从 61.65% 掉到 57.95%。在 200 个族外任务上，Seed 1 达到 1020/1020 安全回合，基线为 689/1020；unseen-MCP 族上为 440/440 对 220/440，且 Seed 1 没有 exact-lure 或 forbidden-read 尝试，基线分别有 79 和 52 次。外部基准上，MetaTool 准确率从 81.9% 提升到 83.6%（p=4.55e-4），FORTIS Task 2 shared-parse 过权限率从 43.28% 降到 40.72%（p=2.11e-5）；在 ToolPrivBench 默认提示下基线与 Seed 1 过权限率分别为 45.2% 和 45.0%，无显著差异，但在 privilege-aware 提示下分别降到 41.2% 和 37.9%。400 步 continuation 后，50 任务验证集安全成功率从 67.75% 升到 90.50%，内部 500 任务安全成功率从 98.48% 微升到 98.76%，MetaTool 基本不变，ToolPrivBench 默认提示过权限率从 45.04% 降到 38.05%（-6.99 pp），privilege-aware 提示下从 37.87% 降到 26.65%。

## experiment_design

评估设计分层且明确。内部完整验证集包含 500 个留出任务：276 个普通任务各采样 4 代，224 个安全密集任务各采样 8 代，每个策略共 2,896 个回合；内部检查点和消融使用其中 206 个任务组成的 routine 子集，每任务 8 代。任务目录为 2,000 个任务，训练 1,500、族内验证 300、族外验证 200；族内任务改变词汇、内容、答案字段和模板以阻止奖励黑客，族外任务引入假外部读取、日志/数据变换、保留最小权限选择和新 MCP 消息模式等新结构，但继续使用同一套 broker、沙箱和 verifier 约定。外部确定性评估使用全部 544 个 ToolPrivBench 场景、FORTIS 两个任务共 600 和 1,543 项，以及固定 1,000 项 MetaTool 子集（每子任务 200 项），外部评估均 temperature=0。内部统计使用配对任务簇 bootstrap 区间，外部匹配场景使用单侧配对 McNemar 检验。提示消融在固定 206 任务集和 1,648 回合/策略/提示条件下进行，包括完整提示、去掉最小权限措辞的提示、一行短提示。Continuation 用 200 个 ToolPrivBench-informed 纠正任务和 200 个原始训练任务，纠正任务覆盖瞬时重试、有界重试、便利陷阱、必要时升级和等权限替代，并用关键词匹配检查与 ToolPrivBench 的污染。

## result_interpretation

结果整体支持“任务条件最小权限可以被后训练习得”的结论。最大的内部 gain 来自确定性验证器和奖励信号使模型学会在完成任务的同时避免越权；完成任务成功率上升说明安全提升不是靠拒绝执行。提示消融显示训练后的行为已经内化而非依赖提示模板：去掉安全措辞甚至改成一行提示，安全成功率几乎不变，而基线降解明显。族外任务上的绝对优势说明模型学到的是任务相对权限原则，而非死记任务模板。外部基准方面，MetaTool 提升说明安全训练没有损害一般工具能力；ToolPrivBench 上默认提示无差异、privilege-aware 提示才显现差距，这提示在不熟悉的环境中，已学到的最小权限行为可能需要任务说明才能被“解锁”。400 步 continuation 进一步说明框架能迁移：矫正训练使 ToolPrivBench 过权限率低于“带提示的基线”，说明即使不是完全无偏的泛化测试，框架仍能通过少量新域任务获得显著安全收益。内部饱和速度很快也说明训练效率高，但作者同时指出这可能意味着任务多样性不足，需要更难、更模糊的任务来进一步区分模型能力。

## limitations

论文承认若干局限：continuation 研究从已训练的 Seed 1 出发且是事后进行的，并不是完全无偏的泛化测试；训练稳定性在没有冷启动措施时没有保证，多个种子中只有 Seed 1 表现稳定，部分种子在 unseen MCP 族上出现格式错误；任务全部由合成方式生成，限制了对真实生产仓库或服务中行为的推断；奖励函数中的各项权重是人工选择且未做系统优化，未必是最优组合；任务目录多样性不足，内部高效饱和可能掩盖了困难任务上的能力差异；外部泛化并不均匀，例如在 ToolPrivBench 的某些失败升级族上训练策略仍有回退；权威维度、权重和充分包络本身也编码了可能不完全正确的人为判断。

## reproduction

训练配置：Qwen3.5-4B，rank 32 LoRA、alpha 64、bfloat16；使用直接 Dr. GRPO 训练一个 1,500 步 epoch；每行采样 8 条轨迹，每条轨迹 4,096 token 完成预算，最多 20 次工具调用，裁剪参数 0.2，batch size 1，梯度累积 8，无 KL 项，无监督微调；总计三个种子，约 12,000 条轨迹（由每个种子 1,500 步 × 8 轨迹推得）。运行环境为 Ubuntu 24.04 under WSL，使用两张 32GB NVIDIA RTX 5090 级 GPU，训练框架 TRL 1.5.1，推理 vLLM 0.22.1。Continuation 训练为 400 步，使用 200 个 ToolPrivBench-informed 纠正任务和 200 个原始训练任务，框架组件不变。外部评测固定 temperature=0。由于实现细节来自 source register 摘录，部分超参数以外的代码级细节（如具体 verifier 实现、任务生成脚本）在现有材料中不可见。
