## MODIFIED Requirements

### Requirement: 按主题发现有限数量的 arXiv 候选
系统 SHALL 接收主题、领域、数量上限和可选 UTC 发现窗口，并返回窗口内按发布时间从新到旧排列且不超过该上限的 arXiv 论文候选；该能力是“每日最新若干篇”的有界信息流，不承诺在窗口内论文数超过上限时构建穷尽档案。

#### Scenario: 运行一次主题发现
- **GIVEN** 调用方提供合法主题、领域和正数上限但没有旧发现水位
- **WHEN** 生产图运行候选发现
- **THEN** 返回的候选数量不超过上限
- **THEN** 每个候选包含稳定 source ID、标题、来源 URL、领域和带时区发布时间

#### Scenario: 运行一次增量主题发现
- **GIVEN** 调用方提供合法的 UTC 窗口下界和上界
- **WHEN** 生产图运行候选发现
- **THEN** 系统只选择发布时间晚于下界且不晚于上界的候选
- **THEN** 当合格候选超过上限时系统只保留最新的有限数量候选

#### Scenario: 来源返回非法发布时间
- **GIVEN** arXiv 条目缺少发布时间或时间格式无效
- **WHEN** 系统归一化该条目
- **THEN** 系统不得把该条目作为增量候选发布
- **THEN** 运行记录安全的发现失败而不是猜测时间

### Requirement: 持久化研究方向可以异步触发生产图
系统 SHALL 使用已持久化方向的检索词、隔离领域标识、服务端数量上限和可选发现窗口调用现有生产图，并 SHALL 将图回执汇总为包含触发类型与窗口的可持久化运行结果；初始、手动和计划入口均不得降低既有去重、来源锚点、独立语义支持和完整 bundle 门禁。

#### Scenario: 执行方向初始化批次
- **GIVEN** 一个 queued 初始化运行引用了存在的研究方向
- **WHEN** 后台执行器开始运行
- **THEN** 生产图接收 run ID、方向检索词、隔离领域标识和最多 3 篇的数量上限
- **THEN** 运行结束后保存 `initial` 触发类型以及候选、发布与失败计数

#### Scenario: 执行方向计划批次
- **GIVEN** 一个 queued 计划运行包含确定的发现窗口
- **WHEN** 后台执行器开始运行
- **THEN** 生产图只处理窗口内最新且不超过该方向每日上限的候选
- **THEN** 运行结果保存 `scheduled` 触发类型、窗口上下界以及候选、发布与失败计数

#### Scenario: 部分候选失败
- **GIVEN** 同一批次中至少一篇候选失败且至少一篇成功发布
- **WHEN** 后台执行器汇总处理回执
- **THEN** 运行状态为 `partial_failed`
- **THEN** 已发布知识保持可读、可检索，失败候选不阻断其他候选

#### Scenario: 进程在活动运行期间重启
- **GIVEN** 持久化运行仍为 `queued` 或 `running`，但其执行进程已经终止
- **WHEN** 新运行时实例初始化任务存储
- **THEN** 系统把遗留活动运行标记为 `failed`
- **THEN** 用户可以手动重试，系统不得把遗留状态显示为仍在运行

## ADDED Requirements

### Requirement: 自动生产复用相同的证据与幻觉门禁
计划运行 MUST 经过与初始化和手动运行相同的临时解析、来源锚点校验、独立蕴含判断、Markdown 原子发布和索引更新路径；调度器不得直接生成或写入知识。

#### Scenario: 计划运行产生不受支持的来源事实
- **GIVEN** 每日计划运行的抽取草稿包含无法由锚点证据支持的来源事实
- **WHEN** 质量门禁评估该草稿
- **THEN** 系统不得把该草稿标记为 `published` 或写入检索索引
- **THEN** 运行回执记录安全的失败或需审核结果

#### Scenario: 计划运行通过全部质量门禁
- **GIVEN** 每日计划运行的草稿通过全部自动门禁
- **WHEN** 系统发布该知识
- **THEN** 系统先原子写入带来源链接和证据侧车的版本化 Markdown
- **THEN** 系统再更新可重建检索索引和 source ID 去重记录
