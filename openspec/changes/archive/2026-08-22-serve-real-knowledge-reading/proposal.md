## Why

当前首页时间线只能读取知识资产元数据，阅读正文仍是前端写死的演示内容，因此“个人科研知识库”的核心阅读体验还没有连接真实的版本化 Markdown。需要先补齐只读详情闭环，让用户看到实际发布内容和来源链接，同时如实区分知识 chunk 锚点与尚未实现的论文级来源定位。

## What Changes

- 新增已发布知识资产的只读详情 API，按知识 ID 返回当前版本的元数据与 Markdown 正文。
- 首页选择时间线项目时加载对应详情，并渲染真实 Markdown、证据等级、版本及来源链接；当前锚点只按知识文本展示，不宣称可跳转到论文页码。
- 明确处理加载中、知识不存在、资产损坏和后端不可用状态；演示内容只作为明确标注的空库引导，不冒充真实知识。
- 保持现有问答范围行为：从详情页“问这篇论文”时继续传递当前知识 ID。
- 保持来源可见性：前端不改写正文中的主张类型和锚点字符串，不将未发布或无法校验的文件展示为正式知识。
- 明确依赖：论文级证据定位、机器可读 claims 和 source anchor 映射由后续 `preserve-durable-evidence-provenance` change 定义；本变更不得伪造该能力。
- 非目标：不实现历史资料筛选、Markdown 编辑器、PDF 阅读器、通用文件上传、全文原文保存、知识资产删除或多用户权限。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `knowledge-reading`: 在现有时间线元数据和论文范围问答入口之上，增加当前版本去重、已发布知识详情读取、真实 Markdown 展示、来源可见性以及失败/空状态。

## Impact

- 后端：`research_pulse/api/` 增加详情 DTO 与路由；文件知识仓增加按 ID 解析当前发布版本的只读接口。
- 前端：`frontend/src/api.ts`、类型定义和阅读页状态管理；新增受控 Markdown 渲染依赖。
- 测试：增加详情 API、非法/不存在资产、前端生产构建验证。
- 数据与安全：继续以 `knowledge/` Markdown 为事实来源，不读取或持久化论文 PDF；返回内容仅来自已发布且哈希校验通过的资产；本变更不新增论文级证据定位字段。
