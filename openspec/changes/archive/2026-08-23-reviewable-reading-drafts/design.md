## Context

当前生产图在质量门禁失败时返回 `needs_review`，并保持旧的已发布版本不变，但失败草稿没有可供用户查看的持久化入口。现有知识仓的 Markdown/provenance 是正式知识来源，RAG 只消费通过门禁的当前版本；论文 PDF、Docling 完整输出和解析全文仍必须是单次运行内的临时材料。

## Goals / Non-Goals

**Goals:**

- 保存可重解析、可脱敏的待审核精读预览和质量问题。
- 让前端展示待审核内容，但明确隔离当前正式版本和 RAG。
- 让确认发布重新走正式解析、抽取、质量门和不可变发布路径。
- 保持旧当前版本可回滚、可继续问答，并让拒绝/失败可追踪。

**Non-Goals:**

- 不把待审核草稿直接提升为已发布 bundle。
- 不持久化 PDF、完整解析全文、EvidenceBlock 全量集合、prompt 或 provider 原始响应。
- 不做多人权限、评论协作、通用文档审批或任意 Markdown 编辑器。

## Decisions

### 1. 草稿采用“受限 Markdown + 元数据”双边界

待审核正文写入 `knowledge/review-drafts/<safe-knowledge-id>/<draft-id>.md`，只包含精读段落、状态、来源 URL、质量问题摘要和可读证据边界；PostgreSQL 保存 draft ID、knowledge ID、状态、哈希、创建时间、来源 URL 和安全问题代码。草稿目录不被现有 `KnowledgeReader` 时间线扫描，也不被 `PostgresResearchRAG` 投影。

替代方案是只存数据库 JSON，但会削弱现有 Markdown 阅读/哈希校验的一致性；直接写入正式 `knowledge/papers` 则会污染当前版本选择，因此不采用。

### 2. “确认发布”是重新运行，不是复制草稿

由于原始 EvidenceBlock 和解析全文不能持久化，确认按钮不能直接把待审核 Markdown 变成正式 bundle。确认后使用 draft 的 source ID/URL 重新下载和解析论文，复用正式生产路径生成新草稿，并再次执行质量门、独立蕴含判断、manifest 和 RAG 发布。只有新运行通过才更新 `is_current`；失败只更新审核状态并保留旧版本。

替代方案是保存全量临时证据等待确认，虽然可以避免重跑，但违反原始材料不落盘边界并扩大敏感数据风险。

### 3. 审核 API 只返回安全字段

读取接口返回 draft ID、状态、标题、版本候选、精读正文、来源链接、质量问题、证据边界和创建时间，不返回 PDF 路径、数据库连接串、prompt、完整 provider 响应或绝对文件路径。确认/拒绝接口使用幂等状态转换：只有 `needs_review` 可操作，已拒绝/已发布/已过期返回冲突或安全不可用状态。

### 4. 前端采用“正式版本优先，审核预览并列”

论文详情继续以当前已发布版本作为默认正文和问答范围；存在草稿时增加待审核提示和预览面板。预览面板明确“不会用于 RAG”，展示质量问题和差异，并提供确认发布、拒绝和刷新状态。没有正式版本时可以只展示预览，但禁用论文问答。

## Risks / Trade-offs

- [重复模型调用] 确认需要重新下载、解析和调用模型 → 以单论文、单次确认边界限制成本，并记录阶段回执。
- [来源变化] arXiv URL 内容可能在两次运行间变化 → 重新运行记录新的版本和内容哈希，不覆盖旧版本；若无法复现则保持 `needs_review`。
- [草稿泄露未验证内容] 用户可能把预览当成事实 → 前端显著标注待审核，API/RAG 层同时强制隔离，不能只依赖 UI。
- [草稿积累] 多次失败会产生多个草稿 → 按 knowledge ID 保留有限的最近草稿，清理只删除审核元数据和生成 Markdown，不触及正式 bundle；清理策略作为后续运维任务。

## Migration Plan

1. 增加草稿元数据表/受限目录和读取 DTO，不改变现有正式 bundle。
2. 将 `needs_review` 回执接入草稿写入；对历史失败回执不自动回填，避免猜测 provider 内容。
3. 增加审核 API 和前端只读预览，先验证不会进入时间线/RAG。
4. 增加确认/拒绝状态机；确认只触发重新生产，成功后走现有发布顺序。
5. 完成真实论文、旧 schema-v2、失败回滚和浏览器验收后再归档 change。

## Open Questions

无。MVP 对同一 knowledge ID 只允许最新的 `needs_review` 草稿进入确认流程；更早的草稿保留为只读历史记录，不可确认发布。
