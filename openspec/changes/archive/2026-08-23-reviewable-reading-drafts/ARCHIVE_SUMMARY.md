# 归档摘要

## 变更目标

为未通过自动质量门禁的论文精读提供隔离的待审核草稿、可见的论文阅读预览，以及确认发布前的重新校验闭环。待审核正文和质量回执不进入当前知识版本、默认时间线或 RAG；只有重新通过质量门禁并明确确认后，才生成新的不可变知识版本。

## 主 Specs 同步

- 更新 `knowledge-quality`：人工确认不能绕过锚点、facet、数字一致性和独立蕴含门禁。
- 更新 `knowledge-reading`：论文详情页可展示隔离的待审核精读预览，并明确其不会进入 RAG。
- 更新 `knowledge-vault`：待审核草稿与当前 bundle、manifest、processed identity 和派生索引隔离。
- 新增 `reviewable-reading-drafts`：审核草稿隔离、重新质控发布和前端预览/拒绝/确认行为契约。

## 用户可见行为

- 论文详情页同时保留当前正式版本和待审核精读预览；预览显示“待审核”、质量问题、证据边界、来源链接，并提示不会用于问答。
- 拒绝草稿后，待审核区域隐藏，当前正式正文、“问这篇论文”入口和 RAG 检索范围保持不变。
- 确认发布必须重新执行质量门禁；通过后生成新 current 版本，旧版本保留为历史版本，RAG 只投影通过校验的新版本。
- 当前知识与待审核草稿均不存在时，页面返回安全的不可用状态，不回退为静态演示正文。

## 实现与安全边界

- 审核草稿使用独立文件和 PostgreSQL 元数据边界，禁止保存 PDF、完整解析全文、prompt 或 provider 原始响应。
- 确认发布复用标准发布路径，不接受伪造的 `passed` 回执；写入、门禁或索引失败均保留旧 current bundle，不产生半成品回答 chunk。
- 为 Windows 长路径场景增加草稿路径短键（安全前缀加哈希），避免长知识 ID 或测试运行标识导致草稿无法读取。

- `npm run verify:markdown`：通过。
- `npm run build`：通过。
- `openspec validate --specs`：12 项通过。
- `openspec validate --all --strict`：16 项通过。
- 真实本地浏览器验收：通过。实际待审核草稿在论文详情页显示预览和拒绝操作；拒绝后 API 列表为空，当前知识版本和“问这篇论文”入口保持不变；验收 fixture 已清理。
