# 9.5 只读工具并发准入记录

结论：本阶段不开放并发白名单，所有研究与 Workspace 工具继续使用 `serial` 策略。

原因：现有 facade 尚未分别提供线程安全证明，Agent adapter 也没有“并发完成、按原调用顺序交付模型”的确定性批处理接口。压力门禁还发现旧 Dispatcher 在等待超时后会过早释放串行锁，而 Python handler 线程仍在运行；该问题已改为由 worker 在线程完整生命周期内持锁。

已验证边界：

- 超时后仍在运行的 handler 不会与下一工具 handler 重叠。
- Attempt 已取消时，并发到达的调用均在预算授权处停止，handler 调用数为零。
- `BudgetLedger` 的计量和取消状态由锁保护。
- 当前注册的只读工具没有任何 `thread_safe_read` 准入项，因此不存在未经证明的并行执行。

后续只有在具体工具实现、资源键冲突检测、确定性结果排序和取消传播四项均有独立压力证据后，才能逐项加入显式白名单。
