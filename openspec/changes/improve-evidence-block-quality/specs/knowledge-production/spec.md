## ADDED Requirements

### Requirement: 生产路径消费结构化证据候选并安全处理 fallback
系统 SHALL 在论文生产中优先使用默认解析器返回的结构化证据候选，而非将 Markdown 固定长度前缀直接视为事实来源。系统 MAY 对明确降级的公式、表格、图注或复杂版式调用已配置的补强解析 adapter；未配置、失败或超出成本边界时 MUST 保留降级状态，不得以另一篇论文、伪造文本或无来源总结替代。

#### Scenario: 默认解析得到合格结构块
- **WHEN** 默认解析器返回满足质量门的结构化证据候选
- **THEN** 系统用这些候选驱动既有结构化抽取、独立判断和发布路径

#### Scenario: 补强解析不可用
- **WHEN** 某个低质量块请求补强但相应 adapter 未配置或执行失败
- **THEN** 系统保留该块的降级原因，并按 facet 覆盖门禁阻止或要求复核，不得静默把该块描述为已解析

### Requirement: 精读正文按章节携带受控证据引用
系统 SHALL 要求将要持久化的每个精读章节分别声明其使用的 EvidenceBlock ID，并在服务端丢弃未知、不可用或来源不匹配的 ID。整篇共享的一组 block ID MUST NOT 被视为每个章节均有证据。模型仍不得自行提供来源摘录、页码、bbox、解析状态或发布资格。

#### Scenario: 实验章节声明自己的证据
- **GIVEN** 深度阅读输出同时包含方法与实验章节
- **WHEN** 模型返回逐节证据引用
- **THEN** 系统分别保存和验证两个章节的 block ID，实验数字只能使用实验章节自己的合格引用

#### Scenario: 章节只引用未知 block
- **GIVEN** 一个精读章节只声明了不在本次解析材料中的 block ID
- **WHEN** 服务端解析深度阅读输出
- **THEN** 系统丢弃未知引用并将该章节标记为证据不足，不得把整篇其他章节的引用借给它

### Requirement: Facet 候选选择保持有界且质量优先
系统 SHALL 在固定字符和块数量预算内按 facet 选择候选，并以语义适配、来源清洁度、定位完整度及正文或表格自包含性作为优先级。若某 facet 有多个合格候选，系统 SHALL 提供多于一个候选供证据投影选择；若没有合格候选，系统 MUST 保持该 facet 缺失并进入审核，不得退回短标题、caption 或不可用公式补足数量。

#### Scenario: 一个 facet 有多个合格候选
- **GIVEN** 方法 facet 有两个合格正文块且均在输入预算内
- **WHEN** 系统构造证据投影输入
- **THEN** 两个候选都可见并按完整度排序，模型不被迫使用单一最短块

#### Scenario: 实验 facet 只有表题残片
- **GIVEN** 实验章节没有完整正文或表格证据，只有一个表题残片
- **WHEN** 系统构造证据投影输入
- **THEN** 实验 facet 保持无候选，后续质量门返回 `needs_review`
