# Incremental Scheduling

## Purpose

为个人研究方向提供可暂停、幂等且可观察的每日自动论文生产，使知识库在无人值守时持续获得经过同一质量门禁的新知识，同时明确单进程 MVP 的运行边界。

## Requirements

### Requirement: 已启用方向每天触发一次计划运行
系统 SHALL 按服务端配置的每日时间和时区，为每个已启用研究方向创建一次计划生产运行；暂停方向 MUST 被跳过，且服务停机期间错过的周期不自动逐次补跑。

#### Scenario: 每日触发到期
- **GIVEN** 调度器已启用且存在两个启用方向和一个暂停方向
- **WHEN** 配置的每日触发时间到达
- **THEN** 系统分别为两个启用方向提交计划运行
- **THEN** 暂停方向不产生计划运行

#### Scenario: 服务在触发时间之后启动
- **GIVEN** 服务在当日触发时间之后启动且当日没有计划运行
- **WHEN** 调度器完成启动
- **THEN** 系统从下一个未来触发时间开始调度
- **THEN** 系统不为停机期间的每个错过周期创建补跑任务

### Requirement: 计划触发必须幂等且不与活动运行重叠
系统 MUST 保证同一方向、同一计划时刻最多存在一个计划运行，并 MUST 在该方向已有 `queued` 或 `running` 运行时跳过本次提交而不终止其他方向的调度。

#### Scenario: 同一计划时刻被重复提交
- **GIVEN** 某方向在该计划时刻已经存在计划运行
- **WHEN** 调度回调因重入或重复启动再次提交相同计划时刻
- **THEN** 系统复用或跳过已有运行
- **THEN** 不创建第二个同计划时刻的运行

#### Scenario: 方向已有手动活动运行
- **GIVEN** 一个启用方向已有 `queued` 或 `running` 手动运行
- **WHEN** 每日调度尝试为该方向创建计划运行
- **THEN** 系统跳过该方向并记录安全的跳过结果
- **THEN** 其他启用方向仍正常提交

### Requirement: 一个方向的故障不得阻断其他方向
系统 SHALL 隔离单个方向的创建或执行故障，并 SHALL 让已创建的计划运行沿用现有终态和安全错误摘要契约。

#### Scenario: 一个方向提交失败
- **GIVEN** 多个方向在同一时刻到期且其中一个方向无法创建运行
- **WHEN** 调度器遍历到期方向
- **THEN** 失败方向留下不含敏感信息的错误记录
- **THEN** 后续方向仍被尝试提交

### Requirement: 调度状态可以被安全观察
系统 SHALL 暴露调度器是否启用、配置时区、每日执行时间和下一次计划时间；响应 MUST NOT 包含 API Key、数据库连接串、完整异常堆栈或原始 provider 响应。

#### Scenario: 查询启用的调度器
- **GIVEN** 调度器已按合法配置启动
- **WHEN** 客户端查询调度状态
- **THEN** 响应包含 `enabled=true`、时区、每日时间和下一次计划时间
- **THEN** 响应不包含任何敏感配置

#### Scenario: 调度器被配置为关闭
- **GIVEN** 服务端明确关闭每日调度
- **WHEN** 客户端查询调度状态
- **THEN** 响应包含 `enabled=false` 且下一次计划时间为空
- **THEN** 手动创建和重试方向的能力保持可用
