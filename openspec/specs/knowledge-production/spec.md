# Knowledge Production

## Purpose

定义已经实现的论文发现、UTC 增量窗口、临时解析、知识抽取和隔离发布行为；该能力提供每日最新有限数量的信息流，但不承诺穷尽归档或细粒度断点恢复。

## Requirements

### Requirement: 按主题发现有限数量的 arXiv 候选
系统 SHALL 接收主题、领域、数量上限和可选 UTC 发现窗口，并返回窗口内按发布时间从新到旧排列且不超过该上限的 arXiv 论文候选；该能力是“每日最新若干篇”的有界信息流，不承诺在窗口内论文数超过上限时构建穷尽档案。

#### Scenario: 运行一次主题发现
- **GIVEN** 调用方提供合法主题、领域和正数上限但没有旧发现水位
- **WHEN** 生产图运行候选发现
- **THEN** 返回的候选数量不超过上限
- **THEN** 每个候选包含稳定 source ID、标题、来源 URL、领域和带时区发布时间

#### Scenario: 运行一次增量主题发现
- **GIVEN** 调用方提供合法的 UTC 窗口下界和上界
- **WHEN** 生产图运行候选发现
- **THEN** 系统只选择发布时间晚于下界且不晚于上界的候选
- **THEN** 当合格候选超过上限时系统只保留最新的有限数量候选

#### Scenario: 来源返回非法发布时间
- **GIVEN** arXiv 条目缺少发布时间或时间格式无效
- **WHEN** 系统归一化该条目
- **THEN** 系统不得把该条目作为增量候选发布
- **THEN** 运行记录安全的发现失败而不是猜测时间

### Requirement: 源材料只在单篇处理调用内存在
系统 MUST 使用临时 PDF 和解析结果生成证据片段，且不得把完整 PDF、解析正文或模型提示词放入 LangGraph 状态。

#### Scenario: 解析并处理一篇论文
- **GIVEN** Docling 能够解析候选论文
- **WHEN** 生产服务完成该候选的抽取与质检
- **THEN** 图状态只包含候选 ID 和处理回执
- **THEN** 发布资产不包含论文全文

### Requirement: 每个候选独立失败和去重
系统 SHALL 在处理前按 source ID 跳过已处理论文，并 SHALL 将单篇异常转换为失败回执而不中断同一批次的其他候选。

#### Scenario: 候选已经成功处理
- **GIVEN** source ID 已存在于持久化去重表
- **WHEN** 再次处理该候选
- **THEN** 返回 `skipped_duplicate`
- **THEN** 不再次解析、抽取或发布

#### Scenario: 一篇候选解析失败
- **GIVEN** 批次包含多篇候选且其中一篇解析抛出异常
- **WHEN** 批次执行
- **THEN** 该候选返回安全的 `failed` 回执
- **THEN** 其他候选仍被处理

### Requirement: 合格草稿先写知识仓再写索引
系统 SHALL 仅把质量门禁批准的草稿转换为 `published`，并把 source ID 与完整 bundle 交给可恢复发布边界；该边界 SHALL 先提交 Markdown、provenance 与 manifest，再更新 ResearchRAG 索引和 source ID 去重记录。只有 manifest 达到 `indexed` 后，本次候选才作为成功发布返回。

#### Scenario: 草稿通过全部自动门禁
- **GIVEN** 草稿没有 blocking 或 review 级质量问题
- **WHEN** 生产服务发布草稿
- **THEN** Markdown、provenance 与 manifest 首先进入个人研究仓
- **THEN** 已发布资产被摄取到检索索引、记录 source ID 且 manifest 变为 `indexed`

#### Scenario: 知识提交后派生索引失败
- **GIVEN** 已提交 bundle 通过全部内容与来源校验，但索引或 source ID 去重写入失败
- **WHEN** 生产服务处理该候选
- **THEN** 候选返回安全的失败回执且不声称本次发布完整成功
- **THEN** 已提交 bundle 和恢复 manifest 保留，恢复入口可以在不重新解析、抽取或质检论文的情况下完成发布

### Requirement: 持久化研究方向可以异步触发生产图
系统 SHALL 使用已持久化方向的检索词、隔离领域标识、服务端数量上限和可选发现窗口调用现有生产图，并 SHALL 将图回执汇总为包含触发类型与窗口的可持久化运行结果；初始、手动和计划入口均不得降低既有去重、来源锚点、独立语义支持和完整 bundle 门禁。

#### Scenario: 执行方向初始化批次
- **GIVEN** 一个 queued 初始化运行引用了存在的研究方向
- **WHEN** 后台执行器开始运行
- **THEN** 生产图接收 run ID、方向检索词、隔离领域标识和最多 3 篇的数量上限
- **THEN** 运行结束后保存 `initial` 触发类型以及候选、发布与失败计数

#### Scenario: 执行方向计划批次
- **GIVEN** 一个 queued 计划运行包含确定的发现窗口
- **WHEN** 后台执行器开始运行
- **THEN** 生产图只处理窗口内最新且不超过该方向每日上限的候选
- **THEN** 运行结果保存 `scheduled` 触发类型、窗口上下界以及候选、发布与失败计数

#### Scenario: 部分候选失败
- **GIVEN** 同一批次中至少一篇候选失败且至少一篇成功发布
- **WHEN** 后台执行器汇总处理回执
- **THEN** 运行状态为 `partial_failed`
- **THEN** 已发布知识保持可读、可检索，失败候选不阻断其他候选

#### Scenario: 进程在活动运行期间重启
- **GIVEN** 持久化运行仍为 `queued` 或 `running`，但其执行进程已经终止
- **WHEN** 新运行时实例初始化任务存储
- **THEN** 系统把遗留活动运行标记为 `failed`
- **THEN** 用户可以手动重试，系统不得把遗留状态显示为仍在运行

### Requirement: 自动生产复用相同的证据与幻觉门禁
计划运行 MUST 经过与初始化和手动运行相同的临时解析、来源锚点校验、独立蕴含判断、Markdown 原子发布和索引更新路径；调度器不得直接生成或写入知识。

#### Scenario: 计划运行产生不受支持的来源事实
- **GIVEN** 每日计划运行的抽取草稿包含无法由锚点证据支持的来源事实
- **WHEN** 质量门禁评估该草稿
- **THEN** 系统不得把该草稿标记为 `published` 或写入检索索引
- **THEN** 运行回执记录安全的失败或需审核结果

#### Scenario: 计划运行通过全部质量门禁
- **GIVEN** 每日计划运行的草稿通过全部自动门禁
- **WHEN** 系统发布该知识
- **THEN** 系统先原子写入带来源链接和证据侧车的版本化 Markdown
- **THEN** 系统再更新可重建检索索引和 source ID 去重记录

### Requirement: 运行持久化不包含原始论文材料
系统 MUST 只在运行记录中保存方向/运行标识、状态、计数、时间和安全错误摘要，不得保存候选摘要、PDF、完整解析文本、模型提示词、API Key 或完整 provider 响应。

#### Scenario: 持久化成功或失败运行
- **GIVEN** 生产图返回回执或抛出异常
- **WHEN** 系统更新运行记录
- **THEN** 持久化字段仅包含受限运行元数据和安全摘要
- **THEN** 临时源材料仍遵守单篇处理生命周期并在运行后释放

### Requirement: 生产路径消费结构化证据候选并安全处理 fallback

系统 SHALL 在论文生产中优先使用默认解析器返回的结构化证据候选，而非将 Markdown 固定长度前缀直接视为事实来源。系统 MAY 对明确降级的公式、表格、图注或复杂版式调用已配置的补强解析 adapter；未配置、失败或超出成本边界时 MUST 保留降级状态，不得以另一篇论文、伪造文本或无来源总结替代。

#### Scenario: 默认解析得到合格结构块

- **WHEN** 默认解析器返回满足质量门的结构化证据候选
- **THEN** 系统用这些候选驱动既有结构化抽取、独立判断和发布路径

#### Scenario: 补强解析不可用

- **WHEN** 某个低质量块请求补强但相应 adapter 未配置或执行失败
- **THEN** 系统保留该块的降级原因，并按 facet 覆盖门禁阻止或要求复核，不得静默把该块描述为已解析
