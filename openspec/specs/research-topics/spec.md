# Research Topics

## Purpose

让个人科研用户从界面创建并持久化关注方向，立即启动初始化生产，控制每日自动更新，并在不暴露原始论文材料或敏感配置的前提下查看运行结果和重试失败任务。

## Requirements

### Requirement: 用户可以创建持久化研究方向
系统 SHALL 接收方向名称和论文检索关键词，生成稳定的 topic ID 与隔离领域标识，并以已启用状态和默认每日候选上限 3 持久化后返回该方向；名称与检索词为空、过长或仅含空白时 MUST 拒绝创建。

#### Scenario: 创建合法研究方向
- **GIVEN** 用户提供合法的方向名称和论文检索关键词
- **WHEN** 用户提交新增方向表单
- **THEN** 系统返回持久化 topic ID、名称、检索词、领域标识、创建时间、启用状态、每日上限和可空发现水位
- **THEN** 新方向默认启用且后续列表请求仍能读取这些字段

#### Scenario: 创建非法研究方向
- **GIVEN** 名称或检索关键词为空、仅含空白或超过接口限制
- **WHEN** 用户提交新增方向表单
- **THEN** 系统返回输入校验错误
- **THEN** 不创建方向或生产运行

### Requirement: 创建方向时启动受限初始化运行
系统 SHALL 在创建研究方向时为其建立一次最多处理 3 篇候选的初始化运行，并 SHALL 在论文下载、解析或模型调用完成前返回 topic 与 run ID；运行只能复用现有质量门禁和完整 bundle 发布路径。

#### Scenario: 创建方向并接受初始化运行
- **GIVEN** 研究方向输入合法且数据库可用
- **WHEN** 用户提交创建请求
- **THEN** 接口返回 topic 与处于 `queued`、`running` 或终态的 run
- **THEN** HTTP 请求不等待整批论文生产完成

#### Scenario: 缺少 DeepSeek 配置
- **GIVEN** 方向已经持久化但服务没有 `DEEPSEEK_API_KEY`
- **WHEN** 初始化运行开始执行
- **THEN** 运行进入 `failed` 并返回稳定配置错误码
- **THEN** API 不返回密钥、内部文件路径或 provider 原始响应

### Requirement: 用户可以查看方向和运行状态
系统 SHALL 返回研究方向列表及每个方向最近一次运行，并 SHALL 按 run ID 返回 `queued`、`running`、`completed`、`partial_failed` 或 `failed` 状态、候选数、发布数、失败数和安全错误摘要。

#### Scenario: 初始化运行完成
- **GIVEN** 生产图已经为一批候选生成处理回执
- **WHEN** 客户端查询该 run ID
- **THEN** 响应包含终态和候选、发布、失败计数
- **THEN** 响应不包含 PDF、解析全文、模型提示词或完整异常堆栈

#### Scenario: 方向列表为空
- **GIVEN** 数据库中没有研究方向
- **WHEN** 用户请求方向列表
- **THEN** 系统返回空列表
- **THEN** 前端显示新增方向引导而不是伪造方向

### Requirement: 失败或已完成方向可以手动重试
系统 SHALL 允许用户为已有方向创建新的受限运行，但同一方向存在 `queued` 或 `running` 运行时 MUST 拒绝并发重试。

#### Scenario: 重试终态运行
- **GIVEN** 方向最近运行已经结束
- **WHEN** 用户点击重新抓取
- **THEN** 系统创建新的 run ID 并异步执行同一方向检索词

#### Scenario: 重复触发活动运行
- **GIVEN** 方向已有 `queued` 或 `running` 运行
- **WHEN** 用户再次触发运行
- **THEN** 系统返回冲突响应和现有活动 run ID
- **THEN** 不启动第二个并发批次

### Requirement: 用户可以暂停或恢复方向的自动更新
系统 SHALL 允许用户暂停或恢复已存在方向；暂停只影响未来计划触发，MUST NOT 删除方向、历史运行、已发布 Markdown 或检索索引，并且用户仍可手动触发该方向。

#### Scenario: 暂停已启用方向
- **GIVEN** 一个方向处于启用状态
- **WHEN** 用户暂停自动更新
- **THEN** 系统持久化 `enabled=false` 并返回更新后的方向
- **THEN** 已发布知识和当前活动运行不被取消或删除

#### Scenario: 恢复暂停方向
- **GIVEN** 一个方向处于暂停状态
- **WHEN** 用户恢复自动更新
- **THEN** 系统持久化 `enabled=true`
- **THEN** 该方向从下一个未来每日周期重新参与调度且不补跑暂停期间的每一天

### Requirement: 用户可以设置受限每日候选上限
系统 SHALL 允许用户把某一方向的每日候选上限设置为 1 至 3；非法数值 MUST 被拒绝，且修改只影响之后新创建的运行。

#### Scenario: 修改每日候选上限
- **GIVEN** 一个已存在方向当前每日上限为 3
- **WHEN** 用户把上限修改为 2
- **THEN** 系统持久化并返回每日上限 2
- **THEN** 之后的计划运行最多选择 2 篇候选

#### Scenario: 提交越界上限
- **GIVEN** 用户提供小于 1、大于 3 或非整数的每日上限
- **WHEN** 用户保存方向设置
- **THEN** 系统返回输入校验错误
- **THEN** 原有设置保持不变

### Requirement: 方向保存成功发现水位
系统 SHALL 为每个方向保存可空的上次成功发现水位，并 SHALL 只在论文来源查询和候选归一化成功后推进该水位；来源查询失败时 MUST 保留旧水位。

#### Scenario: 增量发现成功但没有新候选
- **GIVEN** 一个方向具有旧发现水位且来源查询成功
- **WHEN** 本次时间窗口没有新候选
- **THEN** 系统仍把发现水位推进到本次窗口上界
- **THEN** 运行以零候选的成功终态结束

#### Scenario: 来源查询失败
- **GIVEN** 一个方向具有旧发现水位
- **WHEN** arXiv 查询或候选归一化失败
- **THEN** 系统不修改该方向的发现水位
- **THEN** 运行进入带安全错误摘要的失败终态

### Requirement: 前端反馈初始化进度并刷新知识时间线
前端 SHALL 在创建或重试后轮询对应运行；运行达到终态时 SHALL 停止轮询，并在存在新发布知识时刷新真实知识时间线。前端还 SHALL 展示方向启用状态、每日候选上限、上次成功发现时间和计划运行触发类型。

#### Scenario: 运行发布了新知识
- **GIVEN** 前端正在轮询一个运行且其发布数大于零
- **WHEN** 运行进入 `completed` 或 `partial_failed`
- **THEN** 前端停止轮询并刷新知识时间线
- **THEN** 用户可以选择新出现的真实精读详情

#### Scenario: 页面在运行期间卸载
- **GIVEN** 前端正在轮询生产运行
- **WHEN** 用户离开页面或组件卸载
- **THEN** 前端停止该页面的轮询请求
- **THEN** 后台生产运行不受客户端离开影响

#### Scenario: 查看计划运行
- **GIVEN** 某方向最近一次运行由每日调度触发
- **WHEN** 用户查看方向列表
- **THEN** 前端把该运行标识为自动更新并显示其终态或当前状态
- **THEN** 前端不把计划运行误标为用户手动操作
