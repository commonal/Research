# Research Pulse 产品规格（2026-08-24 定稿）

> 本文档综合此前多轮确认的产品决策,是后续开发、改造与面试叙事的基准。
> 目标读者:自己 + codex(改知识库生产)/ 面试官(讲项目时)。全部为**已拍板的判断**,不是候选方案。

## 一、产品定位

**个人科研知识库,服务于「人读」与「RAG 问答」两条消费路径。**

- 核心事实资产 = **给人读的、归纳好的 Markdown 知识笔记**；少量被选择的关键图片可作为该版本的附属展示资产，但不是独立事实来源。
- 后台生产(LangGraph 编排, arXiv → Docling → 精读 → 门禁 → 发布)是**底座**,不是产品本身。
- 产品亮点 = **受控的知识生产 + 可溯源的 RAG 问答 + 按需回溯原文的补充闭环**。

## 二、三层模型(核心架构判断)

> 核心思想:把"给人读的笔记"、"给机器核验的证据"、"可回溯的原文原料"分成三层,不揉进一个文件。

| 层 | 内容 | 角色 | 给谁用 |
|---|---|---|---|
| **Layer A · 笔记** | 归纳好的 Markdown + 少量被选择的解释性图片资产 | **知识库主体 / RAG 主索引**；Markdown 是事实文本，图片只辅助理解 | 人读 + RAG 检索 |
| **Layer B · 证据** | typed claims + 证据锚点 + 原文短摘(≤1000 字符)+ SHA-256(provenance sidecar) | 引用溯源 / 门禁核验 | RAG 引用、质量门禁 |
| **Layer C · 原始材料** | 原始 PDF + MinerU/Docling 完整解析产物 | **按需回溯原文的补充源**(深查、重读、证据核查) | RAG 知识不足分支、核查 |

**关键决策:**
- **Layer A 与 Layer B 分文件存储**。笔记只写人类可读内容,英文原文摘录、锚点、乱码表格一律不进正文,只存在于 provenance sidecar。
- **知识库的规范事实主体是文本**。可提交 `knowledge/` 下由具体笔记引用的少量图片资产；Layer C 的 PDF、页面全量截图和完整解析产物**不进知识库、不提交 git**。
- 同一份 Markdown 两个视图:人读 = 完整笔记;RAG = 索引时投影成 N 个语义自包含的块(按 heading + 语义切,带标题路径、锚点)。

## 三、知识库生产规范(Layer A 怎么写才是"人话")

- 结构:`一分钟总结 → 背景与问题 → 方法思想 → 实验与结果 → 结论与限制 → 复现线索(可选) → 你的疑问/延伸`
- 风格:像一篇真正的研究读书笔记——流畅叙述、有判断、有直觉、信息密度高;**不用每句对齐原文**。
- 关键结论句尾可嵌轻量引用记号(如 `[c3]`),RAG 命中该段时顺记号去 Layer B 拿锚点。人读时几乎无感。

### 论文精读主流程

```text
Canonical PaperIR（完整、有序、含结构化公式/表格和视觉元数据）
→ 一次全文 PaperModel
→ 同次生成 SectionExplanationContract
→ 程序生成并校验 CoverageLedger
→ 选择性素材规划与必要视觉读取
→ v2 直接长文中文 Writer
→ 事实/数字/公式/表格/素材门禁与盲读验收
→ 仅在高优先级证据缺口存在时触发 ReadingTarget 补读
```

**已确定的写作与成本决策：**

- 完整有序 PaperModel 是默认阅读状态；不再默认执行 `Global Skim → 多轮 Target Loop`，也不从 Unit Memo 拼装论文主线。
- v2 的直接长文 Writer 是当前质量基线。Writer 应围绕问题、方法机制、实验逻辑和边界自然展开，不按章节平均压缩，也不靠统一字数配额扩写。
- `CoverageLedger` 由程序从 PaperModel 与素材决策生成，核心论证、每组关键实验、must-preserve fact、局限和 inline 素材必须恰好有一个章节落点。
- `SectionExplanationContract` 与 PaperModel 同次生成，描述每节要解决的读者问题、必要前提、推理链、实验槽位、素材职责、过渡与完成条件；独立 `SectionDepthPlan` 只在义务无法分配或跨节冲突时作为一次修复，不是固定模型调用。
- 完整 LaTeX 与结构化 HTML 表格走文本模型；只有方法图、趋势图或结构无法从文本恢复的表格在安全真实图片存在且具有不可替代解释价值时走视觉模型。
- `inline | reference | omit` 由解释价值、完整性、不可替代性和去重决定；数量上限只作成本熔断器，不设必须选择多少素材的指标。
- `ReadingTarget` 只解决 PaperModel 已明确记录的高优先级材料/证据缺口，不负责把正文写长、重排章节或重复阅读已经覆盖的内容。

**质量判定：**未读过原论文的人应能回答为什么做、解决什么、怎么解决、实验如何设置和验证、最关键结果以及不能说明什么。固定长度只能作为观察值，不能单独把用户认可且 CoverageLedger/证据/盲读均通过的笔记判失败。

## 四、质量门禁(从"逐句对账"放宽为"关键结论有源")

- 保留:问题 / 方法 / 实验 / 局限 四类 `source_fact` facet 全部有锚点支撑 → 过门。
- 放宽:叙述性、解释性句子**允许模型归纳综合**,不逐句/逐个数字对齐原文。
- 无法锚定的判断 → 降级为 `agent_inference` / `reading_question`,**不阻断整篇发布**。
- 目标:让笔记写出"人话",同时可信度不塌。

## 五、RAG 问答主线

> 直接用知识库作为 RAG 源,不需要另造一套"给 RAG 的库"。

```
用户提问
 → [主] 检索 Layer A 笔记(embedding 检索,切块自包含)
 → 证据够? ── 是 → 回答生成,带 Layer B 锚点引用
        └── 否 → [分支] 打开 Layer C:
                 → 用 source_id 定位 originals/ 内 parse.md
                 → 在原文上加深检索 / 重新精读,补足证据
                 → 仍不够 → interrupt 问用户"是否新增检索论文/网页?"
```

- **当前瓶颈(待攻关)**:检索栈仅 PostgreSQL FTS,缺 dense embedding / RRF / MMR / reranker。这是要补的核心技术点,也是简历亮点。
- 技术选型建议:embedding 库(PostgreSQL pgvector 或独立库)、切块策略、是否 rerank、引用怎么拼回原文。

## 六、原始材料缓存 Layer C(已定:按 source_id 全量保留)

**目录结构:**
```
originals/
  <source_id>/
    source.pdf       # 原始 PDF
    source.html      # 可用时保留网页原文
    mineru/          # MinerU 完整解析产物
    docling/         # Docling 完整解析产物
    normalized/      # 可重读的 Canonical PaperIR 输入
    fetch.json       # URL、下载时间、sha256、来源类型
```

**规则:**

| 项 | 规则 |
|---|---|
| 归属 | Layer C 原料缓存,不属于 Layer A/B 知识库资产 |
| 生命周期 | 按 source_id **全量保留,不清理**;重读/精读覆盖同名文件 |
| git | **`originals/` 排除在 git 外**(二进制、体积、非文本资产);知识库只提交 `knowledge/` |
| 可重建性 | `fetch.json` 记录来源 URL + 时间 + 哈希;arXiv 可重下,本地/私有来源靠缓存保住 |
| 一致性 | 知识库资产应能在 `originals/<source_id>/` 找到对应原料;找不到则回退"仅凭来源 URL 重建" |

> 历史教训：“不保留 PDF”是已废除的临时约束。现行口径是：**规范知识主体为 Markdown，少量选中图片可随版本保存；完整原始材料按 source_id 缓存，不进知识库、不进 git。**

## 七、README 措辞修正(需落实)

README 中多处“不会保存 PDF 或解析全文”应使用新口径——**完整 PDF/解析产物只作 Layer C 原料缓存；笔记可携带少量选中的解释性图片资产。**相关段落：`运行一次真实精读生产批次`、`验证全文解析(可选)`、`目录职责`。

## 八、求职定位对接(已确认叙述方向)

- **REA 已放弃**(定位没想清、功能联动差)。research-pulse 成为唯一主线项目。
- 定位 ="证据工程 / 评估基础设施":让 RAG 的事实来源可信 + 端点离线评估门禁 + 按需回溯原文。
- 与 REA 的叙事切分不再需要(REA 弃用)。
- 差异化钩子:多数人说"我做过 RAG",你说"我做了让 RAG 可信的评测与门禁基础设施,知识不足时能回溯原文补证据"。
