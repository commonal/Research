# Research Pulse 简历项目收束基线

> 状态：进行中（2026-09-13）
>
> 本文件只描述“能被招聘者复现和核验的主线”。代码、测试和脱敏运行回执优先于旧交接文档或聊天记录。

## 1. 项目主张

Research Pulse 不是“给论文做摘要的聊天框”，而是一个面向科研任务的持久化 Research Harness：

```text
研究问题 → 论文/网页证据 → 研究地图与候选问题 → 用户确认焦点
        → 继续检索与综合 → 可追溯产物
        ↘ 失败/停止/重启后仍可恢复
```

简历上只保留这条主张。论文翻译、解释和笔记生产是支撑能力，不单独作为产品中心。

## 2. 当前能力分层

### 已有工程能力（代码层）

- Workspace / Session / Run 的持久化模型；
- 受控研究工具和证据块引用；
- 论文、网页、普通回答等路径的路由入口；
- 研究焦点确认和继续执行；
- Attempt、预算、取消、失败恢复和事件轨迹；
- PDF 精确选区的翻译、解释、提问入口；
- 前端公开运行轨迹、折叠技术细节和启动脚本。

### 仍需补齐的产品证据

- 一条真实 PDF 的端到端黄金路径回执；
- 引用回跳到正确页码和证据块的独立验收；
- 预算耗尽、网络中断、工具失败、手动停止四类恢复回执；
- 与普通单轮 LLM/RAG 的基线对比；
- 固定评估任务集、指标和可重复运行方式。

## 3. 唯一黄金路径

验收必须使用真实论文和真实后端，不得用 fixture 代替最终证据：

1. 导入或打开真实 PDF，等待解析完成；
2. 在文本层精确选择一段内容；
3. 分别执行翻译、解释、基于选区提问；
4. 回答保留证据引用，点击引用跳回正确页码并高亮；
5. 围绕论文提出一个“边界/不足/可继续研究”的问题；
6. Agent 读取证据并生成候选研究问题；
7. Agent 在用户决策点暂停，用户选择或编辑研究焦点；
8. 继续执行同一个 Run 的研究上下文，产生新的证据和研究产物；
9. 在预算耗尽、网络中断、手动停止或工具失败后恢复；
10. 刷新页面或重启后，Run、Attempt、事件和证据仍可追溯。

## 4. 验收矩阵

| 领域 | 需要证明的事实 | 证据形式 | 当前状态 |
| --- | --- | --- | --- |
| 真实 PDF | 选区对应用户实际选择的文本 | 浏览器录屏 + run receipt | 待最终验收 |
| 选区回答 | 翻译/解释/提问都能返回并显示边界 | 截图 + API 记录 | 主流程已有，需统一回执 |
| 引用定位 | 引用能跳到正确页码/块；无法定位时有明确降级 | 逐条点击记录 | 待验收 |
| 研究推进 | 用户确认焦点后，下一轮确实沿该焦点检索 | 前后两轮 workspace JSON + 真实 HTTP receipt | 已通过（浏览器展示仍可复核） |
| 恢复 | 失败不覆盖旧 Attempt，继续不重复副作用 | 状态转移 + 事件序列 | 有机制测试，需真实 UI 回执 |
| 质量 | 结论、证据、推断分层，不能用未读内容冒充证据 | 评审表 + 引用检查 | 待建立基线 |
| 路由 | 自动路由可解释，且用户能手动覆盖 | 期望路由/实际路由记录 | 待建立基线 |
| 性能 | 记录 p50/p95 延迟、token 和失败率 | 脱敏运行汇总 | 待采集 |

## 5. 评估任务集

固定任务定义在 [`../evals/workbench_golden_tasks.jsonl`](../evals/workbench_golden_tasks.jsonl)。每个任务必须记录：

- 输入和前置材料；
- 期望路由和允许的替代路由；
- 最低证据要求；
- 必须发生的用户介入点；
- 失败、取消和继续时的状态不变量；
- 可复核的 receipt 路径。

第一阶段先使用 9 个任务，不追求统计学结论，先确保每个关键状态都有可重复案例。任务集稳定后再扩展到 20 个以上。

配对记录完成后，使用 `scripts/run-baseline-eval.ps1` 生成 `summary.json` 和 `report.md`。评估器只汇总脱敏计数、状态、延迟和 token；引用正确性、证据支持度等字段必须由真实运行或人工复核填入，不能由脚本猜测。

## 6. 必须报告的指标

### 研究质量

- 引用定位准确率；
- 证据覆盖率（结论是否有对应证据）；
- 事实、推断、未知边界是否分开；
- 自动路由正确率与手动覆盖成功率；
- 用户确认焦点是否改变下一轮检索和产物。

### 可靠性

- 四类异常的恢复成功率；
- 重复点击继续的幂等性；
- 刷新/后端重启后的状态恢复率；
- 旧 Attempt 是否保持不可变、事件是否连续。

### 体验和成本

- 选区回答 p50/p95 延迟；
- 完整研究路径耗时；
- token、外部搜索次数和失败重试次数；
- 用户需要手动修正路由或焦点的比例。

指标在首次完整运行前标记为 `UNKNOWN`，不能用估计值填充。

## 7. 基线对比

使用同一篇论文和同一组问题，至少比较：

1. 普通单轮 LLM/RAG；
2. Research Pulse 工作台。

比较引用准确性、证据覆盖率、研究方向连续性、异常恢复、延迟和 token 消耗。没有这张对比表，简历只能证明“做了一个系统”，不能证明“这个系统解决了更难的问题”。

## 8. 简历展示包

收束完成后只保留以下展示材料：

- 一页 README：定位、架构、启动、限制；
- 一张生命周期图；
- 一条真实 PDF 黄金路径录屏；
- 一条“失败 → 继续 → 恢复”的录屏；
- 脱敏 JSON receipt 和评估汇总；
- 基线对比表；
- 明确的已知限制清单。

## 9. 收束规则

在 P0 黄金路径、恢复矩阵和基线对比完成前，暂停新增研究功能。任何新需求先判断是否直接提升这三项证据；否则进入后续 backlog。
